# 第 8 章 · 输入归一化

> **上一章我们有了什么**：反向传播、Adam、mini-batch。一次更新的五步。
>
> **这一章要补什么**：第 3 章末尾的伏笔——把 x 的范围从 (−1, 1) 放大到 (−10, 10)，同样的学习率就飞了。
> 观测的 61 项单位五花八门：关节速度可以到 ±8，投影重力只在 ±1 之间。喂给网络前得先"把它们拉到同一个尺度"，
> 这叫**归一化**。它看起来是个小细节，却是仓库里被列为"不变量"的一条：**归一化器必须烘进导出的 ONNX**，
> 忘了这一步，策略在仿真里好好的，到真机上完全不动。这一章讲清为什么。
>
> **本章新词**：归一化、在线统计、冻结、烘焙。
> **需要的前提**：第 4 章的标准化 $(x-\mu)/\sigma$，第 7 章的扁碗。

## 8.1 伏笔兑现：范围放大，梯度下降就飞

实验 `ch08_normalization.py` 第 1 节把第 3 章的找直线做了三遍，同一个学习率 0.1、同样 100 步：

```
                   数据             w             b  100 步后损失
-----------------------  ------------  ------------  ------------
            x ∈ (−1, 1)       2.02442       1.00206    0.00993478
          x ∈ (−10, 10)  -1.18873e+79  -6.67242e+76  5.04046e+159
x ∈ (−10,10) 但归一化后       11.9489       1.37738    0.00918465
```

第二行：x 大了 10 倍，损失爆到 $10^{159}$。为什么？损失对 w 的梯度里有一项 $2 e_i x_i$——x 大 10 倍，梯度大 10 倍，
碗在 w 方向陡了 100 倍（梯度是平方项的导数）。这正是第 7 章的**扁碗**：w 方向陡、b 方向平，一个学习率顾不了两头。

第三行：把 x 减去均值、除以标准差再喂进去，同样的学习率又好了。

## 8.2 观测的 61 项有多不齐

实验第 2 节列了各块的典型幅度：

```
                    观测块  维数  典型幅度
--------------------------  ----  --------
      base_ang_vel (rad/s)     3      ±3.0
projected_gravity (无量纲)     3      ±1.0
      joint_pos−HOME (rad)    14      ±0.5
         joint_vel (rad/s)    14      ±8.0
         last_action (rad)    14      ±0.5
        command (混合单位)    13      ±0.4
```

关节速度的数值是投影重力的 8 倍、命令的 20 倍。不处理的话，网络第一层对"关节速度"那 14 列的旋钮就得比其他列小 8–20 倍，
损失地形在这些方向上是扁的——就是 8.1 节的病。

## 8.3 归一化：每一项各自减均值、除标准差

第 4 章 4.4 节讲过：任何量减去它的均值、除以它的标准差，就变成"均值 0、标准差 1"的量。
**对 61 项各做一次**，就是**归一化**（normalization）：

$$\tilde{x}_j = \frac{x_j - \mu_j}{\sigma_j + \varepsilon}\qquad j = 1, \ldots, 61$$

| 符号 | 就是 |
|---|---|
| $x_j$ | 观测的第 j 项 |
| $\mu_j$、$\sigma_j$ | 第 j 项**自己**的均值和标准差（61 项各有一对） |
| $\varepsilon$ | 一个小数 0.01，防止某一项从不变化（$\sigma_j = 0$）时除以 0 |
| $\tilde x_j$ | 归一化后的第 j 项，读"x 波浪" |

归一化后，关节速度和投影重力都在 ±1 左右晃，碗变圆了。

## 8.4 均值和标准差从哪来：在线统计

问题：μ 和 σ 要用"所有观测"来算，可观测是机器人边跑边产生的，永远收不齐。

办法：**每来一批数据，把 μ 和 σ 往这批数据的方向挪一点，不存历史数据。** 这叫**在线**（running）统计。核心一行：

$$\mu_{\text{新}} = \mu_{\text{旧}} + \frac{\text{这批的条数}}{\text{累计总条数}}\,(\mu_{\text{这批}} - \mu_{\text{旧}})$$

读作：新均值 = 旧均值 + 一个比例 × (这批的均值 − 旧均值)。比例是"这批占目前总数的几分之几"——
第一批比例是 1（全信它），第 100 批比例约 1/100（只挪一点点）。方差的更新同理，公式长一点，在实验里逐行写了。

实验第 3 节手写这个更新，和 rsl_rl 的 `EmpiricalNormalization` 类喂同样的 5 批数据，再和"把 5 批攒起来一次算"对比：

```
维  rsl_rl 均值    手写均值    真实均值  rsl_rl std  真实 std
--  -----------  ----------  ----------  ----------  --------
 0   -0.0790712  -0.0790712  -0.0790712    0.916372  0.916372
 1      3.39981     3.39981     3.39981     8.51455   8.51455
 2    -0.973307   -0.973307   -0.973307    0.535507  0.535507
 3      4.94173     4.94173     4.94173      3.1049    3.1049
```

三列完全一致：**在线更新和攒齐了再算，结果一样，但不用存数据。**

## 8.5 训练时更新，推理时冻结

μ 和 σ 在训练中一直在变（每批数据都挪一点）。可**部署到真机后不能再变**——不然同一个观测今天和明天得到不同的归一化结果，策略行为就不稳定。

所以归一化器有两种模式：

| 模式 | 什么时候 | μ、σ |
|---|---|---|
| `train()` | 训练 | 每批更新 |
| `eval()` | 回放、导出、真机 | **冻结**，用最后一次更新的值 |

实验第 4 节验证：切到 `eval()` 后喂离谱的数据，μ 纹丝不动。

## 8.6 烘焙：为什么必须把归一化器装进 ONNX

网络训练时看到的**永远是归一化后的观测**。所以部署时也必须先归一化再喂网络：

$$\text{动作} = \text{网络}\big(\text{归一化}(\text{观测})\big)$$

两种做法：
1. 真机代码自己减 μ 除 σ，再喂网络——真机得知道这 61 对数字，容易出错。
2. **把归一化器和网络合成一个模块一起导出**——真机只管喂原始观测。仓库用这种，叫"烘焙"（bake in）。

实验第 5 节：`baked = Sequential(norm, net)`，验证 `baked(x) == net(norm(x))`。导出 ONNX 导的就是 `baked`。

**忘了烘焙会怎样**：网络拿到的是原始观测，关节速度那一列比训练时大 8 倍，输出完全错。
而且**在仿真里回放看不出来**——回放脚本会自动套归一化器。这就是 `AGENTS.md` 那条不变量的由来：
"Obs normalization is ON → the normalizer must be baked into the ONNX. `scripts/export.py` does this; in-sim play hides the bug."

```python
if obs_normalization:
    self.obs_normalizer = EmpiricalNormalization(self.obs_dim)   # 61 对 μ、σ
...
def get_latent(self, obs, ...):
    latent = torch.cat(obs_list, dim=-1)      # 拼成 61 维
```

```python
def forward(self, x):
    return (x - self._mean) / (self._std + self.eps)      # 8.3 节公式，eps = 0.01

def update(self, x):
    if not self.training:                                 # eval 模式：直接返回（8.5 节的冻结）
```

## 本章小结

- 输入尺度不齐 = 扁碗 = 梯度下降飞或慢。
- **归一化**：61 项各自 $(x_j - \mu_j)/(\sigma_j + \varepsilon)$。
- **在线统计**：每批把 μ、σ 挪一点，不存历史；和攒齐再算结果一样。
- 训练时 `train()` 更新，部署时 `eval()` **冻结**。
- **烘焙**：归一化器 + 网络合成一个模块导出；忘了会在真机上悄悄失效，仿真回放看不出来。

**第 2 部到此结束。** 你现在有了完整的"学习"零件：数据、模型（MLP）、损失（MSE）、优化（Adam + 反向传播），还知道输入要归一化。
