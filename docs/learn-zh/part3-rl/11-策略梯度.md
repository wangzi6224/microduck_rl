# 第 11 章 · 策略梯度

> **上一章我们有了什么**：价值 V、TD 误差 δ、优势 A = "这个动作比平均好多少"，以及学 V 的 critic。
>
> **这一章要补什么**：终于要拧策略网络的旋钮了。目标很直白——**优势为正的动作，把它的概率推高；为负的，推低**。
> 但有个拦路虎：策略输出的是一口钟（概率分布），动作是从钟里**抽**出来的，"抽样"这一步没法求导。
> 解决它的技巧叫 log-derivative trick，是整个策略梯度的心脏。学会它，第 13 章的 PPO 公式就只剩"加个保险丝"了。
>
> **本章新词**：目标函数 J、策略梯度、log-derivative trick、基线、REINFORCE。
> **需要的前提**：第 4 章的 log π 和期望线性，第 10 章的优势。

## 11.1 想做的事：让 J 变大

第 9 章末尾：策略的好坏是平均回报 $J(\theta) = \mathbb{E}[G_0]$。θ 是策略网络的旋钮。

第 3 章教过怎么让一个函数变大——沿梯度走：$\theta \leftarrow \theta + \alpha\nabla_\theta J$（这次是加号，要**最大化**）。

问题：怎么算 $\nabla_\theta J$？$J$ 是一个期望，期望里的随机性来自"从策略里抽动作"，而"抽样"这个操作没有导数。
用第 3 章的话说：J 是个碗，但我们不知道碗面的公式，只能往碗上扔球看它落在哪。

## 11.2 log-derivative trick：把"对抽样求导"变成"对 log 概率求导"

先用最简单的情形——只有一步、动作是离散的几个——把推导走一遍。策略 $\pi_\theta(a)$ 给每个动作一个概率，做了动作 a 得奖励 $R(a)$。

期望写开（第 4 章 4.2 节）：

$$J(\theta) = \sum_a \pi_\theta(a)\,R(a)$$

对 θ 求导。$R(a)$ 不含 θ（奖励是环境给的），只有 $\pi_\theta(a)$ 含 θ：

$$\nabla_\theta J = \sum_a \nabla_\theta\pi_\theta(a)\,R(a)$$

**关键一步**。第 1 章说过 $\ln$ 的导数：$(\ln x)' = 1/x$。用链式法则，$\nabla\ln\pi = \frac{\nabla\pi}{\pi}$，
两边乘 π 得到：

$$\nabla_\theta\pi_\theta(a) = \pi_\theta(a)\,\nabla_\theta\ln\pi_\theta(a)$$

代回去：

$$\nabla_\theta J = \sum_a \pi_\theta(a)\,\big[\nabla_\theta\ln\pi_\theta(a)\,R(a)\big] = \mathbb{E}_{a\sim\pi_\theta}\big[\nabla_\theta\ln\pi_\theta(a)\,R(a)\big]$$

最后一步是第 4 章的期望定义倒着用："Σ 概率 × 某东西" 就是 "某东西的期望"。

**看结果**：右边是一个期望，可以用第 4 章的办法估——**抽很多个 a，对每个算 $\nabla\ln\pi(a)\cdot R(a)$，取平均**。
而 $\ln\pi_\theta(a)$ 是网络输出的显式函数（第 4 章 4.5 节写出来了），能用 `backward()` 求导。抽样这一步被绕开了。

实验 `ch11_reinforce.py` 第 1 节用数值验证（策略 $a\sim\mathcal N(\mu, 0.5^2)$，奖励 $-(a-1)^2$，只有一个旋钮 μ）：

```
                        ∂J/∂μ
--------------------  -------
            有限差分  1.29022
log-derivative trick  1.39365
      理论值 −2(μ−1)      1.4
```

三个数一致（前两个是采样估计，有点噪声）。

> **停一下，自测**：为什么不能直接对"抽样"求导？
> <details><summary>答案</summary>抽样的输出是随机的，没有"输入动一点输出动多少"的确定关系。log-derivative trick 把随机性挪到了期望符号里（$\mathbb E_{a\sim\pi}$），求导的对象变成了确定的函数 $\ln\pi_\theta(a)$。</details>

## 11.3 它在说什么：加权的模仿

$\nabla_\theta\ln\pi_\theta(a)$ 是"往哪拧旋钮能让 a 的概率变大"的方向。乘上 $R(a)$：

- 奖励高的动作：往"让它更可能"的方向拧得多。
- 奖励低的动作：拧得少（奖励为负就反着拧——让它更不可能）。

**策略梯度 = 按奖励加权，模仿自己做过的动作。** 好的多学，坏的少学。这个直觉贯穿 PPO。

## 11.4 方差太大：减一个基线

上面的估计有个毛病：奖励 $R$ 如果全是正数（比如都在 90 到 100 之间），那所有动作都会被"推高"，只是推的力度略有不同——
信号淹没在一个巨大的共同偏移里，估计的**方差**很大（第 4 章：方差大就要更多样本）。

办法：**给奖励减去一个基准 b**（baseline），用 $R - b$ 代替 $R$。惊人的是这**不改变梯度的期望**。一行证明：

$$\mathbb{E}\big[\nabla\ln\pi(a)\cdot b\big] = b\sum_a\pi(a)\frac{\nabla\pi(a)}{\pi(a)} = b\,\nabla\sum_a\pi(a) = b\,\nabla 1 = 0$$

（概率加起来永远是 1，1 的导数是 0。用到了第 4 章的期望线性。）

实验第 2 节，每次 64 个样本估梯度，重复 200 次看散度：

```
估计器（每次 64 个样本）     均值    标准差
------------------------  -------  --------
                 R·∇logπ  1.38697   0.40987
           (R − b)·∇logπ  1.35643  0.280992
```

均值都≈1.4（理论值），标准差从 0.41 降到 0.28。**基线免费降方差。**

最好的基线是什么？**这个状态的价值 $V(s)$**——"平均水平"。于是权重变成 $G - V(s)$，正是第 10 章的**优势** A：

$$\nabla_\theta J \approx \frac{1}{N}\sum_i \nabla_\theta\ln\pi_\theta(a_i\mid s_i)\;\hat A_i$$

读作：对每个样本，"让这个动作更可能"的方向 × "它比平均好多少"，取平均。这就是 **actor-critic**：actor 出动作，critic 给基线。

## 11.5 REINFORCE：把它跑起来

多步的情形只需把 $R$ 换成回报 $G_t$（或优势），每一步各算一项相加。这个算法叫 **REINFORCE**。

对高斯策略（第 4 章），$\ln\pi$ 是显式的，梯度也能手写：$\nabla_\mu\ln\pi = (a-\mu)/\sigma^2$——"动作比均值大，就把均值往上推"。不过实验直接让 torch 算。

实验第 3 节：一维推小车，观测 s 是小车离目标的距离，动作 a 是推力，奖励 $-(s+a)^2$，最优是 $a = -s$。
策略：μ 是一个 1→16→1 的小网络，σ 是一个可学参数。核心五行：

```python
dist = torch.distributions.Normal(mu, std)
a = dist.sample()                              # 抽动作（探索）
logp = dist.log_prob(a)                        # ln π(a|s)
adv = r - r.mean()                             # 减基线（这里用批平均，简化版的 V）
loss = -(adv.detach() * logp).mean()           # ★ 取负号：torch 只会最小化
opt.zero_grad(); loss.backward(); opt.step()   # 第 7 章的五步
```

`loss = -(A · ln π).mean()`——对它求梯度、取负，正好是 11.4 节的公式。`adv.detach()` 表示"优势当常数，不对它求导"。

```
迭代    平均奖励         σ  μ(s=−0.8)       μ(s=0)   μ(s=0.6)
----  ----------  --------  ---------  -----------  ---------
   0    -2.11119         1  0.0228049      0.44159   0.647131
 200   -0.368069  0.631048   0.788799   -0.0124738  -0.572193
1500   -0.034369  0.193376   0.806886  -0.00279371  -0.593939
```

![REINFORCE 学到的策略](../figures/ch11_reinforce_policy.png)

1500 步后 μ(−0.8) → 0.81、μ(0.6) → −0.59：学到了 $a = -s$。σ 从 1 缩到 0.19：越来越确定。

## 11.6 熵：别让 σ 缩得太快

σ 缩到 0，策略就不再探索——万一现在的解不是最好的，它再也发现不了。
第 4 章说过熵 H 随 σ 增大。给损失加一项 $-c\cdot H$（c 是 `entropy_coef`），就是奖励"保持一点随机"：

$$\text{loss} = -\mathbb{E}[\hat A\ln\pi] - c\,H$$

项目里 c = 0.01。太大策略永远乱动，太小过早收敛。wandb 里的 `Mean noise std` 就是在看这个平衡。

## 📍 映射到项目

> 只需看一眼。

**每一步存下 ln π**，`rsl_rl/algorithms/ppo.py` 的 `act()`：

```python
self.transition.actions = self.actor(obs, stochastic_output=True).detach()          # 抽动作
self.transition.actions_log_prob = self.actor.get_output_log_prob(self.transition.actions).detach()   # ln π(a|s)，存起来
```

第 13 章会看到 PPO 要比较"抽动作时的 ln π"和"更新几步后的 ln π"，所以现在就存。

**ln π 的计算**在 `rsl_rl/modules/distribution.py`（第 4 章见过）：`log_prob(a).sum(dim=-1)`——14 个关节相加。

**熵系数**：`microduck_velocity_env_cfg.py` 的 `entropy_coef=0.01`，用在 `ppo.py` 总损失的最后一项 `- self.entropy_coef * entropy.mean()`。

## 本章小结

- 目标 $J(\theta) = \mathbb{E}[G_0]$，想沿梯度上升，但"抽样"不可导。
- **log-derivative trick**：$\nabla\pi = \pi\nabla\ln\pi$，于是 $\nabla J = \mathbb{E}[\nabla\ln\pi(a)\cdot R]$——用样本平均估，$\ln\pi$ 可以 `backward()`。
- 直觉：**按奖励加权，模仿自己做过的动作**。
- **基线**不改变期望但降方差；最好的基线是 V(s)，权重变成**优势** Â——这就是 actor-critic。
- **REINFORCE**：`loss = -(A · ln π).mean()`。**熵项**防止 σ 过早缩到 0。
