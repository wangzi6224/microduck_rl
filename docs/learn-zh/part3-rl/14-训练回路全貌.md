## 14.1 一次迭代：五个动作

训练是同一个循环重复几千次。每一圈叫一次**迭代**（iteration），做五件事：

```
┌─────────────────────────────────────────────────────────────────────────┐
│  ① rollout：4096 只机器人各走 24 步                                       │
│     每步：actor 抽动作 a_t（第 4 章）、critic 估 V_t（第 10 章）、           │
│           记下 ln π(a_t|s_t)（第 11 章）；仿真给 r_t 和下一帧观测；            │
│           归一化器吃进新观测更新 μ、σ（第 8 章）                              │
│                                    ↓  98,304 条 (s, a, r, V, ln π, done)    │
│  ② compute_returns：从后往前算 δ → GAE 的 Â → returns = Â + V（第 12 章）      │
│                                    ↓                                       │
│  ③ 洗牌、切 4 份、过 5 遍（第 7 章），每份：                                   │
│        比率 → 裁剪目标 → 价值损失 → 熵 → 总损失（第 13 章）                    │
│        zero_grad → backward → clip_grad_norm → Adam step（第 7 章）           │
│                                    ↓  20 次更新                             │
│  ④ 量 KL，调学习率（第 13 章 13.5）                                          │
│  ⑤ 打印日志；每 250 次迭代存一次 model_N.pt 并导出 ONNX（第 19 章）             │
└─────────────────────────────────────────────────────────────────────────┘
                              ↑ 扔掉数据，回到 ①
```

**rollout** 就是"让当前策略跑一段、把经历记下来"。**iteration × 24 = 环境步数**，仓库里所有课程表（第 18 章）用的都是环境步数这把尺。

## 14.2 真的跑一次

实验 `ch14_smoke_train.py` 用 64 个环境跑 5 次迭代（仓库 `AGENTS.md` 说的"冒烟测试"，几十秒），
然后把最后一次迭代打印的日志翻译出来。这是它的输出（数字每次略有不同，随机种子固定时完全相同）：

```
             日志行  本次的值                                                       它是什么
-------------------  --------  -------------------------------------------------------------
        Total steps      7680  累计环境步数 = iteration × num_envs × 24（64 env：每次 1536）
    Collection time    0.539s                                跑 24 步仿真的时间（第 5 章 ①）
      Learning time    0.043s                          20 次 PPO 更新的时间（第 13 章 13.6）
    Mean value loss    0.0421                 critic 的 MSE：(V − returns)²（第 13 章 13.4）
Mean surrogate loss   -0.0446                      −L^CLIP 的平均（第 13 章 13.3，负数正常）
  Mean entropy loss   19.8142                   14 维高斯的熵，σ≈1 时 ≈ 19.86（第 4 章 4.6）
        Mean reward      0.17           回合内奖励之和的平均（16 项加权和 × 0.02，第 16 章）
Mean episode length     35.61                                 平均回合长度（步）。摔得快就短
    Mean action std      1.00                            14 个 σ 的平均（第 4 章），初值 1.0
```

逐行说人话：

- **Total steps** 7680 = 5 次迭代 × 64 env × 24 步。4096 env 时每次迭代 98,304。
- **Collection / Learning time**：跑仿真花的时间远多于更新——这就是为什么要 GPU 并行 4096 个环境。
- **Mean value loss** 0.04：critic 估的 V 和 returns 的差的平方。训练初期会先升（critic 从 0 开始学）再降。
- **Mean surrogate loss** −0.04：负的裁剪目标。它的绝对值不重要（优势归一化后均值是 0），**看它别爆炸**就行。
- **Mean entropy loss** 19.81：14 个 σ 都≈1 时熵 = 14 × 1.419 = 19.86（第 4 章实验算过）。它随 σ 下降而下降。
- **Mean reward** 0.17：一回合的总分。5 次迭代的机器人只会乱抖，几十步就摔，所以分数很低。正常训练里这条线会涨到几十。
- **Mean episode length** 35.6 步 = 0.7 秒就摔。目标是 1000 步（20 秒不摔）。
- **Mean action std** 1.00：还是初值。几百次迭代后会慢慢降到 0.3–0.5。

## 14.3 每一项奖励

```
                奖励项  加权后的值
----------------------  ----------
 track_linear_velocity       0.023
track_angular_velocity       0.002
               upright      0.0283
                  pose      0.0071
          body_ang_vel     -0.0238
      angular_momentum          -0
        dof_pos_limits     -0.0006
        action_rate_l2     -0.0984
              air_time      0.0115
        foot_clearance     -0.0003
     foot_swing_height     -0.0015
             foot_slip     -0.0001
       self_collisions     -0.0008
    head_pose_tracking      0.0572
    body_pose_tracking           0
        head_pose_bias           0
  ✓ 所有惩罚项 ≤ 0
```

这是 `Episode_Reward/<名字>`：每一项在一回合里的**加权**贡献（函数值 × 权重 × 0.02 在回合内求和，再除以 20 s）。
所以**满分且跑满 20 秒时，读数恰好等于权重**：`track_linear_velocity` 最高 2.0，`air_time` 最高 3.0 × 2 = 6.0。回合越短读数越小。
两条读法：

1. **惩罚项必须 ≤ 0**。`AGENTS.md` 说这是"每次运行都要检查的不变量"：一个符号写反的惩罚会变成奖励，策略会去"farm"它。实验自动检查了这一条。
2. **权重为 0 的项读数就是 0**（`body_pose_tracking`、`head_pose_bias`），不代表行为——第 18 章课程会在几百次迭代后把它们的权重打开。

第 16 章把这 16 项的公式逐个拆开。

## 14.4 其余几组

```
Curriculum/action_rate_weight: -0.1000     ← 课程当前阶段（第 18 章）：action_rate 权重从 −0.1 起步，1500 次迭代后到 −1.0
Curriculum/standing_envs: 0.0200           ← 2% 的环境命令为零（站着不动）
Curriculum/head_pose_range: 0.0700         ← 头部命令范围还很小
Episode_Termination/fell_over: 1.8750      ← 这次迭代里每个环境平均摔了 1.9 次
Episode_Termination/time_out: 0.0000       ← 没有一个撑到 20 秒
Metrics/twist/error_vel_xy: 0.0335         ← 速度跟踪误差（m/s）
```

**读一个正常训练的方法**（`AGENTS.md` 的话翻译过来）：

| 看什么 | 健康的样子 | 不健康 |
|---|---|---|
| Mean reward | 持续上升 | 平了、或在课程阶段边界处突然下跌（第 18 章） |
| Mean episode length | 上升到接近 1000 | 一直很短 = 学不会站 |
| 主任务项（track_linear_velocity 等） | 真的在涨 | 总分涨但主任务项不涨 = 只在 farm 正则项 |
| 每个惩罚项 | ≤ 0 | 出现正数 = 符号写反 |
| Mean action std | 缓慢下降 | 骤降到 0 = 过早收敛；不降 = 学不到东西 |
| KL / 学习率 | 学习率在 1e-4 ~ 1e-3 之间晃 | 学习率一路掉到 1e-5 = 策略每步变化太大 |

## 14.5 产物


## 📍 映射到项目

> 只需看一眼。

**五个动作的代码**在 `rsl_rl/runners/on_policy_runner.py` 的 `learn()`（第 5 章 📍 贴过）：`act → env.step → process_env_step` 循环 24 次，
然后 `compute_returns`，然后 `update`。日志由 `self.logger` 打印。

**冒烟测试命令**（`AGENTS.md`，每次改配置后必跑）：

```bash
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 64 --agent.max_iterations 5
```

它能抓住 95% 的配置错误：环境建不起来、观测维度不对、某个奖励函数报错、NaN、ONNX 导不出。实验脚本只是给它加了 `--agent.logger tensorboard`（免 wandb 登录）和一个自动翻译。

**正式训练**：`--env.scene.num-envs 4096`，本机 RTX 5070 约 2.6 秒/迭代，1000 次迭代 ≈ 43 分钟，走路需要 4000–6000 次。

## 本章小结

- 一次**迭代** = rollout 24 步 → GAE → 切 4 份过 5 遍共 20 次更新 → 调学习率 → 打日志。**iteration × 24 = 环境步数**。
- 日志每一行对应一个公式：value loss（第 13）、surrogate（第 13）、entropy（第 4）、action std（第 4）、reward 和 episode length（第 9）。
- `Episode_Reward/*` 是加权值：**惩罚项必须 ≤ 0**，权重 0 的项读数就是 0。
- 健康的训练：reward 涨、episode length 涨到 1000、主任务项真的涨、std 缓降。
- 产物：`model_N.pt`（θ）和 `.onnx`（烘焙好的 actor）。
