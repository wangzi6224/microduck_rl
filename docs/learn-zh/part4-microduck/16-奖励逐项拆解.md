## 16.1 总分怎么算

$$r_t = \Delta t\sum_{i=1}^{16} w_i\, f_i(\text{状态}_t)\qquad \Delta t = 0.02$$

| 符号 | 就是 |
|---|---|
| $f_i$ | 第 i 条规则的函数，输入当前状态，输出一个数 |
| $w_i$ | 权重，cfg 里定的 |
| $\Delta t$ | 每步 0.02 s。对相同的连续评分轨迹做时间积分近似，减少采样频率对累计分数的影响；若控制行为或离散代价本身改变，不能保证总分一样 |

## 16.2 符号约定：两种惩罚，一条铁律

mjlab 的习惯：函数返回**非负的代价**（≥ 0，越大越糟），符号放在权重里（负权重）。8 项代价都是这样。

本仓库自己写的一些惩罚（`head_pose_bias_penalty`）返回的是**≤ 0 的数**，配**正**权重。

两种都对，但混用会出事：给一个"返回 ≤ 0"的函数配负权重，负负得正，**惩罚变奖励**，策略会专门去犯这个错（历史上出现过"蹲着蹦"和"故意坐倒"）。
所以有一条铁律（第 14 章实验自动检查了）：**wandb 上每一个惩罚项的 `Episode_Reward/<名字>` 必须 ≤ 0。**

## 16.5 两个权重为 0 的项

- **body_pose_tracking**：躯干姿态跟踪，6 维命令各一个钟取平均。权重 0，**存在只是为了观测里那 6 个槽有对应物**（第 15 章的零填充）。
- **head_pose_bias**：600 次迭代后课程打开到 3.0（第 18 章）。它是本章最有教育意义的一项，单独讲。

### head_pose_bias：只收"直流分量"

$$f = -\,\text{mean}_4\big|\,\text{EMA}_{1s}(q_{head} - cmd)\,\big|$$

| 符号 | 就是 |
|---|---|
| $q_{head} - cmd$ | 头部 4 个关节的跟踪误差（和 head_pose_tracking 一样） |
| $\text{EMA}_{1s}$ | 对误差做 1 秒的**指数滑动平均**：$e \leftarrow (1-\alpha)e + \alpha\cdot\text{err}$，α = 0.02/1.0 |
| $\|\cdot\|$ | 绝对值（L1），不是平方 |
| 负号 | 返回 ≤ 0，配正权重（16.2 节的第二种） |

**它解决的问题**（cfg 注释里的故事）：头占体重 38%，走路时头**必然**随步伐晃。之前想用一个更窄的钟（fine_std = 0.1）逼头部精确跟踪，
结果策略在 300 次迭代后**干脆不走了**——晃是走路的物理必然，罚不掉，只能不走。**这个税是逃不掉的。**

可是"头长期下垂"是逃得掉的（把脖子命令抬高一点抵消重力）。区分两者的办法：**先平均 1 秒**——晃动是正负交替的，平均后抵消；下垂是持续的，平均后留下。
再用 L1 而不是平方：L1 的梯度在大偏差处是常数，不会像钟形那样在远处变平（第 1 章 1.9–1.13 节的问题；这里指评分形状，不是 PPO 直接使用的导数）。

`AGENTS.md` 的话："Price only the escapable part"——**只给逃得掉的那部分定价。**

## 16.6 血泪教训的数学翻译

这些是 `AGENTS.md` 里的规则，每条用前面学过的语言说一遍：

**1. RL 优化的是奖励的字面意思。** 第 11 章：策略梯度只推高"优势为正"的动作，它不知道你"想要"什么，只知道分数。任何没被公式覆盖的自由度都会被利用（用甩头代替翻滚、用侧倒代替前倾）。对策：**把"什么算完成"写成硬性的状态判断**（支撑脚接触、朝向轴检查），不靠小惩罚去"劝"。

**2. 不能有"头奖"。** 一个"到达 X 就每步给分"的奖励，早到一步就多赚一步——策略会不惜一切**提前到达**（暴力冲刺）。对策：跟踪一个**限速的内部目标**（匀速滑动），领先目标不给分，于是"慢"反而是最优。

**3. 别把正奖励绑在坏状态上。** 例如"倒地时给站起来的奖励"——策略会找一个最便宜的"算倒地"的姿势躺着刷分。对策：用进步差分作为塑形思路，例如 $\Delta\cos(\text{倾角})$。但折扣、负差分、终止和重置必须一起处理，不能直接宣称不可刷；严格的势函数形式及条件见 16.10 节。

**4. 两种正则项。** 动作阻断型（body_ang_vel、angular_momentum、pose 的窄 σ）罚的是动态动作**物理上必需**的东西——动态任务里要小。平滑型（action_rate）惩罚相邻动作变化，同样幅度慢慢完成通常代价更低，但不是完全不罚缓慢动作——可以重，但要**在技能出现之后**再加（课程）。任何"尝试税"在技能还没出现时都会让"什么都不做"赢。

**5. 比奖励质量，不比权重。** 同一个 action_rate 权重，在一个正向奖励总量大 4 倍的任务里就弱 4 倍——PPO 看的是**相对**优势（第 12 章的归一化）。

**6. 钟的宽度 ≈ 你还在乎的误差。** 第 1 章 1.9–1.13 节：中间误差区间的奖励差异更明显，这不是直接传给 PPO 的参数梯度。但先问：这个误差策略**逃得掉吗**？逃不掉的（头晃）别用窄钟罚（教训 16.5）。

**7. 乘法组合 vs 加法组合。** 加法的总分可以靠"每项拿 80%"的折中姿势凑高；几个钟**相乘**，任何一项为 0 总分就是 0——逼策略每项都做到。但 σ 要宽到当前策略的分数**看得见**，否则该项给采样学习的奖励差异可能极小，浮点下溢时还会成为零，难以帮助学习。

**8. 关节顶在限位上。** 用 qpos 侧的"接近限位"惩罚；动作侧的惩罚没用，因为宽的 ctrlrange 是故意的（低增益舵机需要超调）。

## 16.7 从物理误差到总奖励，一步都不省略

假设速度命令为 $(0.3,0)$ m/s，实际身体系速度为 $(0.2,0.1,0.05)$ m/s。
前两项是前后和左右，最后一项是竖直速度；竖直目标为 0。

先逐项作差，再平方求和：

$$E_v=(0.3-0.2)^2+(0-0.1)^2+(0-0.05)^2
=0.01+0.01+0.0025=0.0225.$$

这里 $E_v$ **已经是平方误差和**，不能再平方一次。
代进速度核：

$$f_v=e^{-0.0225/0.1}=e^{-0.225}\approx0.798516.$$

权重 2、dt=0.02，这一项实际给 PPO 的单步贡献是：

$$r_v=0.798516\times2\times0.02\approx0.031941.$$

再假设只有两个关节的动作较上步变化了 +0.1 和 −0.2，其余变化为 0，
平滑代价 $c=0.1^2+(-0.2)^2=0.05$。
早期权重 −0.1 时贡献 $0.05(-0.1)(0.02)=-0.0001$；
后期权重 −1 时贡献 −0.001。行为没变，扣分已经变十倍。

若这里只考虑这两项，早期合计约为 0.031841；真实环境还会加上其余项。
这把三个层次分清楚了：**原函数值 f、加权值 wf、按时间积分的单步贡献 dt·wf**。
日志又可能对回合累计值做归一化，见 14.6 节。

## 16.8 每种核在偏差处说了什么

平方代价 $\mathrm{err}^2$：误差从 0.1 变 0.2，代价从 0.01 变 0.04，翻四倍。
L1 代价 $|\mathrm{err}|$：同样变化，代价只翻两倍。
高斯奖励 $\exp(-\mathrm{err}^2/s^2)$：靠近目标给分高，远离目标后加分差异渐小。
它们不是互换的写法，而是在给不同程度的误差定不同价格。

**软限位**可以用一个教学铰链函数说明：
$c(q)=\max(0,q-u)+\max(0,l-q)$，l、u 为软下限和软上限。
在 `[l,u]` 内两项都是 0；超过上限 0.02 rad，代价就是 0.02。
这也是为什么“还没到软边界但一直贴着边走”可能需要另设计接近限位的代价。

**腾空窗口**则没有平滑过渡：在窗口内给 1，窗口外给 0。
它不需要把奖励对腾空时间的导数传给 PPO。不同轨迹是否进入窗口，仍会造成回报差异。
但窗口内所有时刻原始得分相同，并不能单独指定漂亮的步态。
两只脚同时在窗口内可得 2 的代数上界，也不证明期望步态应长期双脚离地。

### 平方和、先平均后指数、指数后平均，是三种目标

两项误差分别为 0 和 s，令标准化平方误差为 `[0,1]`：

| 组合方式 | 计算 | 值 |
|---|---|---:|
| 平方误差求和后取指数 | $e^{-(0+1)}$ | 0.367879 |
| 平方误差平均后取指数 | $e^{-(0+1)/2}$ | 0.606531 |
| 每项取指数后平均 | $(e^0+e^{-1})/2$ | 0.683940 |

函数中 `.mean()` 放在哪一行，会改变评分含义。
前两者分别相当于各项核的乘积与几何平均；最后一种允许做对一部分就拿到对应的部分分。
不能只看到“都是高斯”就认定奖励相同。

## 16.9 为什么先平均误差，再取绝对值

头部周期误差为 `[+0.2,−0.2,+0.2,−0.2]` 时：
平均误差为 0，但平均绝对误差为 0.2。
若误差一直是 `[−0.2,−0.2,−0.2,−0.2]`，两种统计的绝对大小才都为 0.2。
所以“先平均再取绝对值”是在偏向惩罚持续偏置，而不是每一次往返摆动。

EMA 不等于精确的 1 秒滑动窗口。α=0.02 时，每次更新保留旧值的 98%，
历史影响按 $0.98^k$ 衰减，50 步后仍约为 0.364。
若持续误差为 0.2、初始 EMA 为 0，第一步是 0.004，第二步是 0.00792，
50 步后约为 $0.2(1-0.98^{50})=0.127166$。
这解释了为什么罚分不会在偏置刚出现时立刻达到稳态，也解释了为什么回合重置时要处理历史状态。

本项目没有因此对**动作**做 EMA。对评分误差做统计和把执行动作滤波是不同路径，
不能因为奖励里用了 EMA 就在部署端给动作加同样的滤波。

## 16.10 “只付进步的钱”也需要边界条件

先定义 $\Phi(s)$ 为给状态的一个标量进度分，例如“离站直还有多远”转换后的分数；$F_t$ 是额外加到该步奖励的塑形项。
简单差分 $F_t=\Phi(s_{t+1})-\Phi(s_t)$ 在不打折、首尾衔接的路径上会望远镜相消。
但如果把下降的差分裁成 0，只保留上升的奖励，来回摆动就能反复收钱。
回合重置、终止时未结清的状态，也会影响这笔账。

对于折扣目标，常见的势函数塑形形式是：

$$F_t=\gamma\Phi(s_{t+1})-\Phi(s_t).$$

将它乘上 $\gamma^t$ 后累加，中间项才按同一折扣抵消，
留下起点和末尾项。要保持原任务最优策略，还要满足状态势函数、终止处理等条件。
因此工程中的 $\Delta\cos(tilt)$ 是“奖励进步”的直觉，不能无条件说它绝对不可刷，
也不能把它与 γ<1 下的严格势函数塑形定理直接画等号。

**自测**：一项函数返回 −0.2，权重设 −3，这真的是惩罚吗？

**解释**：加权后是 +0.6，再乘 dt 仍为正，实际在奖励这次违反。
检查名称没有用，要把函数输出和权重一起相乘。

```python
alpha = min(1.0, float(env.step_dt) / max(tau_s, 1e-6))          # 0.02 / 1.0
env._head_bias_ema = (1.0 - alpha) * env._head_bias_ema + alpha * err   # 1 秒滑动平均
out = -env._head_bias_ema.abs().mean(dim=-1)                       # L1，取负
```

**加权求和**：`mjlab/managers/reward_manager.py` 的 `compute()`：`value = func(...) * weight * dt`，权重为 0 的项直接跳过。

## 本章小结

- 总分 $= \Delta t\sum w_i f_i$：6 项任务、8 项代价、2 项待课程。满分跑满 20 s 时 `Episode_Reward/x` = 权重。
- **符号铁律**：≥0 的代价配负权，≤0 的自负号惩罚配正权；wandb 上惩罚项永远 ≤ 0。
- 六种核：高斯钟（跟踪、站直、姿态、头）、盒式指示器（air_time）、平方（action_rate）、铰链（限位）、距离×速度（clearance）、L1 的 EMA（head_bias）。
