## 16.1 总分怎么算

$$r_t = \Delta t\sum_{i=1}^{16} w_i\, f_i(\text{状态}_t)\qquad \Delta t = 0.02$$

| 符号 | 就是 |
|---|---|
| $f_i$ | 第 i 条规则的函数，输入当前状态，输出一个数 |
| $w_i$ | 权重，cfg 里定的 |
| $\Delta t$ | 每步 0.02 s。乘它是为了让总分不随控制频率变（50 Hz 和 100 Hz 跑 20 秒总分一样） |

实验 `ch16_reward_curves.py` 第 1 节从真实 cfg 读出全部 16 项：

## 16.2 符号约定：两种惩罚，一条铁律

mjlab 的习惯：函数返回**非负的代价**（≥ 0，越大越糟），符号放在权重里（负权重）。8 项代价都是这样。

本仓库自己写的一些惩罚（`head_pose_bias_penalty`）返回的是**≤ 0 的数**，配**正**权重。

两种都对，但混用会出事：给一个"返回 ≤ 0"的函数配负权重，负负得正，**惩罚变奖励**，策略会专门去犯这个错（历史上出现过"蹲着蹦"和"故意坐倒"）。
所以有一条铁律（第 14 章实验自动检查了）：**wandb 上每一个惩罚项的 `Episode_Reward/<名字>` 必须 ≤ 0。**

## 16.3 六项任务奖励

![奖励核](../figures/ch16_reward_kernels.png)

| 项 | 公式 | 权重 | 讲解 |
|---|---|---|---|
| **track_linear_velocity** | $\exp(-\|\mathbf{v}_{xy} - \mathbf{v}^{cmd}_{xy}\|^2/0.1)$，再加竖直速度的平方 | 2.0 | 第 1 章的核，第 2 章的范数平方。σ²=0.1：误差 0.26 m/s 掉一半 |
| **track_angular_velocity** | $\exp(-(\omega_z - \omega_z^{cmd})^2/0.5)$，再加 roll/pitch 角速度的平方 | 2.0 | 同上，σ² 更宽（转向允许更粗） |
| **upright** | $\exp(-(g_x^2+g_y^2)/0.05)$ | 2.0 | 第 2 章 2.4：倾斜 10° 就只剩一半 |
| **pose** | $\exp\big(-\text{mean}_j[(q_j - \text{HOME}_j)^2/\sigma_j^2]\big)$，只算 10 个腿关节 | 1.0 | "别离站姿太远"。σ 按**是否在走**切换：站着时窄（髋横滚 0.05），走着时宽（膝 0.4）——走路本来就要大幅摆腿 |
| **air_time** | 每只脚：腾空时间在 (0.125, 0.3) s 内计 1，否则 0；命令为零时整项为 0 | 3.0 | **盒式指示器**（图左下）。不是"腾空越久越好"，是"腾空时间要合适"——太短是拖脚，太长是跳 |
| **head_pose_tracking** | $\text{mean}_{4}\exp(-(q_{head} - cmd)^2/0.5^2)$ | 2.0 | 4 个头部关节各一个钟，取平均（不是相乘）——部分跟上给部分分 |

实验第 3 节数了满分时每步能拿多少：

```
                任务项  权重  核最大值  每步最多  1000 步(20 s)最多
----------------------  ----  --------  --------  -----------------
 track_linear_velocity     2         1      0.04                 40
track_angular_velocity     2         1      0.04                 40
               upright     2         1      0.04                 40
                  pose     1         1      0.02                 20
              air_time     3         2      0.12                120
    head_pose_tracking     2         1      0.04                 40
总分上限约 300 分/回合
```

`air_time` 是最大的一块：两只脚各 1 分 × 权重 3——**走路本身是最赚的事**，这是有意的：让"迈步"比"站着"值钱。

## 16.4 八项代价

| 项 | 公式 | 权重 | 在防什么 |
|---|---|---|---|
| **action_rate_l2** | $\|\mathbf{a}_t - \mathbf{a}_{t-1}\|^2$ | −0.1 → −1.0（课程） | 相邻两步动作差的平方。防抖动。**在原始策略输出上算**，scale=1 时 1 弧度差就是 1 |
| **dof_pos_limits** | 超出软限位（90% 量程）的部分之和 | −1.0 | 铰链损失（图中下）：限位内为 0，出去线性涨。防关节撞极限 |
| **body_ang_vel** | $\omega_x^2 + \omega_y^2$（不算 $\omega_z$，转向是命令） | −0.05 | 防躯干乱晃。权重很小——第 16.6 节说为什么 |
| **angular_momentum** | 整机角动量的范数平方 | −0.02 | 同上，更小 |
| **foot_clearance** | $\sum_{\text{脚}}\|h - 0.02\|\cdot\|\mathbf{v}_{\text{脚}}\|$ | −2.0 | 脚在空中移动时离目标高度 2 cm 的距离 × 脚速。慢慢拖脚便宜、快速拖脚贵——防拖地 |
| **foot_swing_height** | 落地那一步：$(h_{\text{峰}}/0.02 - 1)^2$ | −0.25 | 只在落地瞬间结账：这一步抬得够不够 2 cm |
| **foot_slip** | 着地的脚的水平速度平方 | −0.1 | 防打滑。故意很轻：这只机器人转向靠"以脚为轴拧"，重了转不了 |
| **self_collisions** | 自碰撞的接触点数 | −1.0 | 腿别打腿 |

**没有的项也说明问题**：这里没有关节力矩、关节速度、关节加速度惩罚（`mdp.py` 里有这些函数，但走路任务没用）。平滑全靠 `action_rate` + BAM 舵机自己的物理（第 17 章）。

## 16.5 两个权重为 0 的项

- **body_pose_tracking**：躯干姿态跟踪，6 维命令各一个钟取平均。权重 0，**存在只是为了观测里那 6 个槽有对应物**（第 15 章的零填充）。
- **head_pose_bias**：600 次迭代后课程打开到 3.0（第 18 章）。它是本章最有教育意义的一项，单独讲。

### head_pose_bias：只收"直流分量"

$$f = -\,\text{mean}_4\big|\,\text{EMA}_{1s}(q_{head} - cmd)\,\big|$$

| 符号 | 就是 |
|---|---|
| $q_{head} - cmd$ | 头部 4 个关节的跟踪误差（和 head_pose_tracking 一样） |
| $\text{EMA}_{1s}$ | 对误差做 1 秒的**指数滑动平均**：$e \leftarrow (1-\alpha)e + \alpha\cdot\text{err}$，α = 0.02/1.0 |
| $\|\cdot\|$ | 绝对值（L1），不是平方 |
| 负号 | 返回 ≤ 0，配正权重（16.2 节的第二种） |

**它解决的问题**（cfg 注释里的故事）：头占体重 38%，走路时头**必然**随步伐晃。之前想用一个更窄的钟（fine_std = 0.1）逼头部精确跟踪，
结果策略在 300 次迭代后**干脆不走了**——晃是走路的物理必然，罚不掉，只能不走。**这个税是逃不掉的。**

可是"头长期下垂"是逃得掉的（把脖子命令抬高一点抵消重力）。区分两者的办法：**先平均 1 秒**——晃动是正负交替的，平均后抵消；下垂是持续的，平均后留下。
再用 L1 而不是平方：L1 的梯度在大偏差处是常数，不会像钟形那样在远处变平（第 1 章折叠里的问题）。

`AGENTS.md` 的话："Price only the escapable part"——**只给逃得掉的那部分定价。**

## 16.6 血泪教训的数学翻译

这些是 `AGENTS.md` 里的规则，每条用前面学过的语言说一遍：

**1. RL 优化的是奖励的字面意思。** 第 11 章：策略梯度只推高"优势为正"的动作，它不知道你"想要"什么，只知道分数。任何没被公式覆盖的自由度都会被利用（用甩头代替翻滚、用侧倒代替前倾）。对策：**把"什么算完成"写成硬性的状态判断**（支撑脚接触、朝向轴检查），不靠小惩罚去"劝"。

**2. 不能有"头奖"。** 一个"到达 X 就每步给分"的奖励，早到一步就多赚一步——策略会不惜一切**提前到达**（暴力冲刺）。对策：跟踪一个**限速的内部目标**（匀速滑动），领先目标不给分，于是"慢"反而是最优。

**3. 别把正奖励绑在坏状态上。** 例如"倒地时给站起来的奖励"——策略会找一个最便宜的"算倒地"的姿势躺着刷分。对策：**势能式塑形**（potential-based shaping）：只付"进步"的钱——付 $\Delta\cos(\text{倾角})$（这一步比上一步直了多少）而不是 $\cos(\text{倾角})$ 本身。站直了付、待着不付，无法刷。

**4. 两种正则项。** 动作阻断型（body_ang_vel、angular_momentum、pose 的窄 σ）罚的是动态动作**物理上必需**的东西——动态任务里要小。平滑型（action_rate）只罚抖，不罚慢而大的动作——可以重，但要**在技能出现之后**再加（课程）。任何"尝试税"在技能还没出现时都会让"什么都不做"赢。

**5. 比奖励质量，不比权重。** 同一个 action_rate 权重，在一个正向奖励总量大 4 倍的任务里就弱 4 倍——PPO 看的是**相对**优势（第 12 章的归一化）。

**6. 钟的宽度 ≈ 你还在乎的误差。** 第 1 章折叠：导数只在钟腰强。但先问：这个误差策略**逃得掉吗**？逃不掉的（头晃）别用窄钟罚（教训 16.5）。

**7. 乘法组合 vs 加法组合。** 加法的总分可以靠"每项拿 80%"的折中姿势凑高；几个钟**相乘**，任何一项为 0 总分就是 0——逼策略每项都做到。但 σ 要宽到当前策略的分数**看得见**，否则梯度为 0 什么也学不到。

**8. 关节顶在限位上。** 用 qpos 侧的"接近限位"惩罚；动作侧的惩罚没用，因为宽的 ctrlrange 是故意的（低增益舵机需要超调）。

**head_pose_bias 的核心三行**（`mdp.py`）：

```python
alpha = min(1.0, float(env.step_dt) / max(tau_s, 1e-6))          # 0.02 / 1.0
env._head_bias_ema = (1.0 - alpha) * env._head_bias_ema + alpha * err   # 1 秒滑动平均
out = -env._head_bias_ema.abs().mean(dim=-1)                       # L1，取负
```

**加权求和**：`mjlab/managers/reward_manager.py` 的 `compute()`：`value = func(...) * weight * dt`，权重为 0 的项直接跳过。

## 本章小结

- 总分 $= \Delta t\sum w_i f_i$：6 项任务、8 项代价、2 项待课程。满分跑满 20 s 时 `Episode_Reward/x` = 权重。
- **符号铁律**：≥0 的代价配负权，≤0 的自负号惩罚配正权；wandb 上惩罚项永远 ≤ 0。
- 六种核：高斯钟（跟踪、站直、姿态、头）、盒式指示器（air_time）、平方（action_rate）、铰链（限位）、距离×速度（clearance）、L1 的 EMA（head_bias）。
- **只给逃得掉的误差定价**；不设头奖；正奖励别绑坏状态（用 Δ 势能）；尝试税等技能出现再加。
