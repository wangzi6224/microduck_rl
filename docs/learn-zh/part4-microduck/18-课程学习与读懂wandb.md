# 第 18 章 · 课程学习与读懂 wandb

> **上一章我们有了什么**：动作、舵机模型、域随机化。
>
> **这一章要补什么**：走路任务里有 7 个东西**随训练进度变化**：两个奖励权重、一个"站着不动"的环境比例、两个质心随机化范围、两个命令范围。
> 这叫**课程学习**——先易后难。它是一张时间表，读懂它才能读懂 wandb 上"为什么这条曲线在第 500 次迭代突然掉了"。

> **需要的前提**：第 14 章的迭代与环境步，第 16 章的奖励权重。

## 18.1 为什么要课程

小孩先学站再学走。RL 里也一样：一开始就把所有惩罚、所有难度全开，"什么都不做"往往是最优解（摔得少、惩罚少），策略永远不会去尝试走。

**课程学习**（curriculum learning）：从容易的设置开始，等策略学会了再逐步加难。仓库的做法是**阶梯函数**——在预定的环境步数处，把某个参数换成下一档。

## 18.2 尺子：环境步 = 迭代 × 24

第 14 章说过每次迭代每个环境走 24 步。课程表的横轴用的是**环境步**（`common_step_counter`），所以：

$$\text{环境步} = \text{迭代} \times 24$$

cfg 里写 `500 * NUM_STEPS_PER_ENV` 就是"第 500 次迭代"。实验 `ch18_curriculum_timeline.py` 从真实 cfg 里把 7 个课程项全读出来了。

## 18.3 两个权重课程

**action_rate_l2**（动作平滑惩罚）：从很轻开始，等步态出现后逐步加重——

```
环境步 step  = 迭代  权重
-----------  ------  ----
          0       0  -0.1
      12000     500  -0.2
      18000     750  -0.4
      24000    1000  -0.6
      30000    1250  -0.8
      36000    1500    -1
```

为什么不一开始就 −1.0？第 16 章说过：平滑项是"尝试税"，技能还没出现时税太重，"不动"就赢了。

**head_pose_bias**（头部下垂的 L1 惩罚）：**600 次迭代之前权重为 0**——

```
          0       0     0
      14400     600     1
      24000    1000     2
      36000    1500     3
```

cfg 的注释："a posture-precision term is a distraction before a gait exists."——步态没出现之前，姿态精度是干扰。

## 18.4 四个范围课程

```
standing_envs（命令为零、要求站着不动的环境比例）
     0       0  0.02
 12000     500  0.05
 24000    1000  0.15
 48000    2000  0.25

com_range（躯干质心随机偏移 ±m）        head_com_range（头部质心）
     0       0  0.003                        0     0.003
 12000     500  0.005                    12000     0.005
 24000    1000  0.01                     24000     0.01
 36000    1500  0.015

head_pose_range（4 个头部关节的命令范围，弧度）
   0  ((-0.05, 0.05), (-0.05, 0.05), (-0.07, 0.07), (-0.015, 0.015))     ← 机械极限的 5%
 500  ((-0.17, 0.17), (-0.17, 0.17), (-0.21, 0.21), (-0.047, 0.047))     ← 15%
1000  ((-0.39, 0.39), (-0.39, 0.39), (-0.49, 0.49), (-0.11, 0.11))       ← 35%
1500  ((-0.72, 0.72), (-0.72, 0.72), (-0.91, 0.91), (-0.2, 0.2))         ← 65%
2000  ((-1.1, 1.1), (-1.1, 1.1), (-1.4, 1.4), (-0.31, 0.31))             ← 100%
```

![课程时间线](../figures/ch18_curriculum_timeline.png)

两个设计细节（cfg 注释里写的教训）：

- **com_range 封顶 ±15 mm**：之前涨到 ±30 mm，超过了脚掌的支撑范围（脚跟只在踝后 20 mm），质心可能完全落在脚外，机器人被迫用"过度紧张"的步态，向后的平衡永远学不会。回归的时间点和 0.015 → 0.02 → 0.03 的涨幅一一对应。
- **head_pose_range 从 5% 起步而不是 0**：第 15 章的死权重规则——一开始就给一点非零范围，输入神经元才活着。

`body_pose_range` 只有一档（±0.005 m / ±0.05 rad），永远不涨——它就是那个零填充的槽。

## 18.5 课程是怎么"生效"的：改活的管理器

一个容易踩的坑：管理器（Reward/Event/Command Manager）在初始化时**深拷贝**了 cfg。训练中改 `env.cfg.rewards["x"].weight` 是**无效**的——管理器用的是它自己的副本。

课程函数必须改**活的**那份：`env.reward_manager.get_term_cfg(name).weight = ...`。`reward_weight` 课程就是这么写的（📍）。
这条规则同样咬过评估脚本："强制设个初始状态"改了 `env.cfg`，结果什么都没变。

## 18.6 用课程表读 wandb

课程解释了很多"曲线为什么这样"：

| 现象 | 通常的原因 |
|---|---|
| `Episode_Reward/head_pose_bias` 前 600 次迭代是 0 | 权重为 0（第 14 章：读数是加权值） |
| `Episode_Reward/action_rate_l2` 在 500/750/1000… 处台阶式变负 | 权重换档，不是行为变差 |
| Mean reward 在某个课程边界处**突然掉**、之后慢慢恢复 | 难度加了一档（质心、命令范围）。小掉正常；**掉了不恢复** = 节奏太快，下次把这一档往后挪 |
| Mean reward 在边界处掉、且 episode length 也掉 | 新档位让它摔了——比如 com_range 那次 |
| 命令范围涨了但跟踪误差不涨 | 好事，学会了 |

`AGENTS.md` 的规则："当一个指标恰好在课程阶段边界处下跌，说明节奏错了——拉长阶段或推迟引入，**永远不要提前**。"

**看曲线的顺序**（第 14 章表格的课程版）：先看 `Curriculum/*` 现在在哪一档 → 再看 reward/episode length 在这一档内的趋势 → 再对照主任务项是否真的在涨。

## 📍 映射到项目

> 只需看一眼。

**课程定义**：`microduck_velocity_env_cfg.py` 的 `cfg.curriculum[...]`，每项一个 `CurriculumTermCfg(func=..., params={... stages: [{"step": N*24, ...}, ...]})`。

**权重课程的实现**，`src/mjlab_microduck/tasks/mdp.py` 的 `reward_weight`：

```python
term_cfg = env.reward_manager.get_term_cfg(reward_name)   # ★ 改活的管理器，不是 env.cfg
for stage in weight_stages:
    if env.common_step_counter > stage["step"]:           # 环境步超过这一档的起点
        term_cfg.weight = stage["weight"]                 # 最后一个满足的档位生效
return torch.tensor([term_cfg.weight])                    # 这个返回值就是 wandb 上的 Curriculum/xxx
```

"最后一个满足的档位生效"——所以 stages 必须按 step 升序写。范围课程（`com_range_curriculum`、`pose_command_range_curriculum`、`standing_envs_curriculum`）是同样的模式，只是改的是事件/命令管理器里的范围。

**已删掉的两个课程**：mjlab 模板自带的 `command_vel`（速度命令范围逐渐放大）被删了——cfg 注释说它"跑在机器人能力前面"，1000 次迭代后 reward 和 episode length 一起下滑。地形课程只在 `rough=True` 时保留。

## 本章小结

- **课程** = 先易后难的时间表，阶梯函数，横轴是**环境步 = 迭代 × 24**。
- 走路任务 7 项：action_rate 权重 −0.1 → −1.0（1500 迭代）、head_pose_bias 600 迭代后打开、站立比例 2% → 25%、质心 3 → 15 mm、头部命令 5% → 100%、躯干命令永远不动。
- 课程必须改**活的管理器**（`get_term_cfg`），改 `env.cfg` 无效。
- 读 wandb：先看在哪一档，边界处的小掉正常，**掉了不恢复 = 节奏太快，往后挪**。
