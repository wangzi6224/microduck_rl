# 编写规范：每一章都写成第 2 章那样

> **范文**是 [第 2 章 · 向量与矩阵](part1-math/02-向量与矩阵.md) 和它的实验 `labs/ch02_vectors.py`；**条文**是这份文件；
> **自动检查**是 `tests/test_learn_docs.py`（结构）和 `tests/test_learn_labs.py`（实验能跑、数字对得上）。
> 三者说法不一致时，以第 2 章的**实际做法**为准——这份规范不比第 2 章更严。
>
> 写或改任何一章之前：先把第 2 章从头到尾读一遍，再读这份规范。

---

## 1. 读者是谁

做过 Web 前端、数学停在初中（会加减乘除和简单代数；函数、斜率要重讲）、**没读过 torch 代码**的人，一个人自学。
由此得到四条总原则，后面所有条文都是它们的展开：

1. **先有东西可想，再给名字。** 生活场景 → 一个小数字的手算 → 才出术语和公式。读者应该在看到公式之前，就已经用数字把它算过一遍。
2. **一次只加一点。** 一小节里新词不超过两个；大表、大数字（4096、61、197,788）之前先有迷你版。
3. **代码是复核工具，不是阅读门槛。** 正文靠文字、图和手算就能读懂；实验用来验证"我刚才手算的数，机器也算出同一个数"。
4. **不丢内容，也不注水。** 重排不删知识点；篇幅不是指标，覆盖面才是（手算在公式前、图有读图、数字被锁住）。

- 成文例外见文末「成文例外」一节。

## 3. `N.0 先看地图` 怎么写

地图的任务：让读者在进入细节前，知道这一章有哪几样东西、它们怎么连起来、哪两个词最容易混。照第 2 章 2.0 的顺序写：

1. **一句加粗的主旨**，用最朴素的话说完全章（"一个数叫标量；有顺序的一串数叫向量；……"）。
2. **一个生活场景**把这些东西串起来（给机器人做记录：一个分数 → 两个速度 → 三只机器人 → 两个时刻）。
3. **一张总览图** + 紧跟一句 `**读图顺序：**`。
4. **一张概念总表**：每行一个概念，列是"它在回答什么问题"。这张表可以一次列出全章的词（不受"一次不超过两个新词"的限制），前提是表后明说"名字先不背，到了各节再给"。
5. **给最易混的词先贴标签**（第 2 章：空间坐标轴 vs 数据轴；"3 维向量" vs "一维张量"），并说"现在觉得别扭很正常，N.k 节会解释"。
   贴 2–4 条，只贴**本章之内**或**与前面章节**会混的；和后面章节才会混的，留给后面那一章去贴。
   典型的有：概率 vs 密度、三个 σ、V / Q / A、梯度裁剪 vs PPO 裁剪、四只"钟"（物理步 / 环境步 / 迭代 / 回合）。
   **特别留意同一个字母或词在章内换了含义**（第 3 章：x、y 前四节是旋钮，3.5 节变成数据；"陡"先指某一点的坡度，后指整只碗的形状）——这类问题作者自己最难发现。
6. **第一遍怎么读**：按顺序看正文、图和手算；标"进阶"的折叠块可以先跳过；代码是复核工具，不是阅读门槛。
   长章（大致超过 900 行或 12 节）要给一个**歇脚点**：在地图和那一节的末尾各说一句"读到这里，后面几章需要的东西已经齐了；剩下几节第一遍累了可以先跳到 📍 和小结"。

地图里**只贴标签、不下定义**；英文和符号"先不背"。

**反例（旧稿的写法）**：小节第一行就是公式，接着符号表，再贴一段实验输出；能手算的例子在 100 行之后的"详解"里。


旧稿章末"详解块"里的手算，就是要搬到这个位置的材料——**数字原样搬**（见后面的「内容保全」）。

下面这些只在**自然处**使用，不按节摊派（第 2 章全章也只有 1 处"为什么重要"、1 处 ⚠️）：

- `**为什么重要**`：一段话说清这个概念后面哪一章、项目里哪件事要用它。
- 前端类比（读者的母语是 JS）：`Σ` = `for` 循环 / `reduce`；逐项运算 = `map`；期望 = 对样本取平均；`clip` = `Math.min(Math.max(…))`；
  倒序递推 = `reduceRight`；延迟缓冲 = 队列 `push` / `shift`；"改了 `env.cfg` 没生效" = 改了副本没改引用。公式本身就是循环或夹取时才用，两三行即可。
- `> ⚠️`：本章真实存在的经典坑，每个坑一个（最常见的记反、同一个字母两个意思、单位陷阱、"跑得通但意义全错"）。

**按整章计的下限**：折叠自测（`> **停一下，自测**`）至少 3 处，答案一律折叠；长的一节末尾可以放多题自测。

## 5. 新词与符号

- 新词分两级。**主词**：本章要教会的术语，第一次出现时写成 `**中文**（English）`，进开篇的 `本章新词` 清单，每个 H2 小节**不超过 2 个**——超了就拆小节，或者把次要的推迟到用得上的地方。
  **顺带词**：讲解时要用一下的普通词（等高线、噪声、发散、截距……），加粗但不带英文、不进清单，**当场用一句话说清**；每个 H2 也不要超过 2 个（折叠块里的不计）。
  "先不背、第 X 章讲"的名字也算顺带词，别让它们成串进来。**整章也有预算**：主词大致不超过 10 个；超了就看哪些其实该归后面的章。
- 新词之后不再加粗。只是顺带提到、后面才讲的词，写"先不背，第 X 章讲"。任何词、符号、记号（`Σ`、`≈`、下标、科学计数法、对数刻度、"数量级"……）都不能先用后讲。
- 术语表 / 对照表不能替代讲解：一次列出 4 个以上新词的表，要拆成逐个引入；总表可以留在后面当"回看用的索引"，并明说"不用背"。
- 符号表固定三列：`| 符号 | 怎么读 | 就是 |`。希腊字母给读音（"西塔"），运算符给人话（"对 i 从 1 到 n 求和"= for 循环）。
  表格单元里的范数写 `\lVert x \rVert`，不要写 `\|x\|`——竖线会把表格切坏。
- 开篇的 `本章新词` 清单 = 正文里的全部主词，不多不少。

## 6. 先小后大；分清两种数字

- 项目里的真实规模（4096 只机器人、61 维观测、24 步、197,788 个旋钮）出现之前，先用 2–3 个数的迷你版把同一件事做一遍，并明说"这是它的迷你版"。
- **教学构造数字**（为了好认好算而编的，如第 2 章的 1 到 12）要说明是构造的；**实验输出**是脚本真实打印的。两者不混。
- 手算只用读者会的运算；出现平方根、`exp`、科学计数法（`4.5e+34`、`5.35e-09`）时当场用一句话解释。
- **字面值重算**：正文里写成等式的手算，拿等式里**印出来的那几个已经四舍五入的数**重新算一遍也必须成立。`14 × (−0.916) = −12.83` 不行（读者按计算器得 −12.82）；要么多印一位（`14 × (−0.9163) = −12.83`），要么换一组处处自洽的数。自测的答案尤其如此——它是读者唯一的反馈。实验里除了 `round(x, k) == 字面值`，再加一条用字面值重算的 check（`round(14 * -0.9163, 2) == -12.83`）。
- **读者能不能自己验证，分三级**：① 手算；② 浏览器控制台按一下（`Math.log(4.13)`、`Math.exp(-0.5)`）；③ 只能跑实验（10 万个样本、1700 条细条、torch 给的数）。主线上的关键数至少要有 ① 或 ②；只有 ③ 的，读者只能"信"，那就还是配方。

## 7. 折叠块

三种用途，写法固定：

```text
<details>
<summary>进阶：点积的几何意义（现在可跳过）</summary>

正文……（上下各空一行，里面的 Markdown 才会正常渲染）

</details>
```

- **进阶**：严格推导、一般化、边界情形——第一遍读不需要的内容。摘要写 `进阶：……（现在可跳过）`。
- **补课**：读者可能缺的前置知识，留三五句当场够用的话，并链接附录（如三角函数 → 附录 D）。
- **第二遍读**：依赖后面章节才能讲透的预告（"这条导数和 PPO 是什么关系"）。摘要写 `第二遍读：……`，里面只用大白话 + "第 N 章（概念名）讲"，不引入符号。
- **折叠的判据**：把推导折起来之后，主线上不能留下一条读者无法自己验证的"配方"（"偏导数就是这一列的平均"）。至少在折叠外留一句直觉 + 一次读者能手算的核对（比如缩 h 量一遍）。
  折叠块前面那句引导语要能独立成立，不要以冒号结尾——跳过折叠的人不该只读到半句话。
- **自测答案**：引用块里的安全写法如下，`<summary>` 里不放公式，`<details>` 同一行不写 Markdown：

```text
> **停一下，自测**：……题目……
> <details><summary>答案</summary>
>
> 答案正文……
>
> </details>
```

## 8. 图

**标准是第 2 章后五张"课堂式"讲解图**（`ch02_number_to_tensor`、`ch02_vector_coordinates`、`ch02_vector_shapes`、`ch02_matrix_recipe`、`ch02_tensor_address`）：

- 标题写**结论**，不写名词（✓"矩阵乘向量：每行是一份配方"；✗"矩阵乘法示意图"）。
- ①②③ 分步，竖着排；每步有一句灰色的大白话。
- **手算直接写进图里**（`1 × 1 + 0 × 2 + 2 × 3 = 7`），数字与正文、与实验的 `check` 是同一组。
- 中文标注、带单位；配色用 `labs/_draw.py` 的 INK / MUTED / BLUE / GREEN / ORANGE。
  字号：标题、分步小标题、手算、灰色说明句用 17–23（`_draw.py` 的 `FS_*` 常量）；数据图的刻度数字 16；贴在线上的小数字不小于 13。
- 数据图（曲线、等高线、直方图）也要长成课堂式：用 `_draw.py` 的 `data_axes` / `panel_title` / `panel_note` / `arrow`，
  必须加"看这里"的标注——关键点标数值，坐标轴写中文和单位，不出现没解释过的符号；用了对数刻度要在图里和正文各说一句。
- **图上的视觉量要和它声称表示的量成比例**：箭头长度、圈的间距、线的粗细。说"每一步一样长"，画出来就得一样长；教"圈越密坡越陡"，等高线的高度间隔就得相等。做不到就在图上明说（"箭头按 0.08 倍缩小画出"）。
- 要读者从图上读出来的数，必须落在刻度上或单独标出来（教读图的第一张图尤其如此）；主词如果是几何概念（斜率、等高线），第一次出现就要配图。
- 图里不要先于正文出现没讲过的符号；实在要出现，读图段里先交代一句（"图里的 ∂f/∂x 就是下面马上要给的名字"）。原样输出块的表头同理：别让表头把读者该自己发现的规律先说破。
- 缩略的小图（一排 14 口小钟这类）要么保留刻度，要么在图上注明相对主图的缩放；教过"面积 = 概率"之后出现的直方图，要说明纵轴是个数还是密度、几幅之间能不能比高矮。
- 能用图说清的，就不要只给公式。每章大致 4–8 张，以讲清为准。

正文里的写法：

```text
![从原点向右三格、向上四格，终点是(3,4)，直线箭头长度是5](../figures/ch02_vector_coordinates.png)

**这样读图：** 先沿横尺走 3 格，再向上走 4 格，最后看连接两端的斜箭头。……
```

- alt 是一句**完整的描述**（不少于 12 字，最好 20 字以上），看不到图的人读 alt 也知道图在说什么。
- 图后三行内必须有读图段：`**这样读图：**` / `**读图顺序：**` / `### 怎么读上面这张图`。告诉读者先看哪、再看哪、看到什么算看懂了。
- 每个 PNG 只由一个实验的一处 `savefig` 生成；命名 `chNN_内容.png`；同一波次的章之间不共用图。
- 画完**必须自己打开看**：中文没有变方框、文字不重叠、没被裁掉、标题就是结论。

## 9. 实验脚本

- 文件头 docstring 写运行命令和依赖；`from _common import banner, check, done, savefig, table`；画图 `from _draw import …`。
- `banner("K. ……")` 的整数小节顺序 = 正文顺序；**算数和 `check` 放整数小节，画图挂在 `Kb`**（`banner("2b. 把上面这张表画成图：figures/chNN_xxx.png")`）。
  正文"动手实验"的编号清单与整数小节一一对应。
- 手算版与 numpy / torch 版并排打印，然后 `check` 两者一致。
- **正文引用的每一个数字都要有 `check(...)` 锁住**；图里写的数字用同一组变量生成，不手抄。
- 随机实验固定种子。正文散文里引用的数（"门槛是 0.9957"）用 `round(x, k) == 字面值` 锁住；再加一条对照**独立算出的理论值 + 容差**的检查（如最小二乘的精确解、解析的期望值），保证换了种子结论也成立。
- `check` 没对上只打印 ✗、不中断脚本（`done()` 最后汇总成非 0 退出码）；一旦有 ✗，`savefig` 就不再覆盖教材里的图，改存到临时目录。所以"改一改"可以放心让读者改参数。
- **每条"改一改"在实验里有一个标记**：要改的那一行写成 `名字 = 原值  # TWEAK-1: 新值`。`tests/test_learn_labs.py` 会按标记改一份副本去跑：检查变 ✗ 可以，**抛异常不行**——脚本必须能跑到 `done()`。
  作者自己要把三条各实跑一遍；算崩（inf / nan）之后还要画的图，先判断 `np.isfinite(...)`，发散就打印一句说明、跳过这张图。
  带容差的 check，标签里不要写死会随 TWEAK 变的数（用 f-string 打印当前的期望值），否则改了参数还会对着旧数字报 ✓；改完之后打印的表仍应有序、可读（该 `sorted` 的 `sorted`）。
- 同一个数在几个小节里反复出现时，用固定的小数位打印（`num()` 会去尾零，0.406570 会变成 0.40657），全章写法一致。
- 正文里**无语言标记的代码块 = 实验的原样输出**，解释写在块外；示意图、手写的排版用 ```text。
  要贴进正文的表，在实验里就按正文引用的精度打印（`table(..., floatfmt=".4g")`），一张表大致不超过 10 行 × 5 列；原样输出块是给读者核对用的，不要让正文读起来像实验报告——能用一句话说清的就别贴整张表。
- 注释不写源码行号（行号会漂）；写文件名 + 函数名。
- **最后一个整数小节核对"映射到项目"**：用 `_common.lines_in_order` 检查正文引用的常数和源码行在源文件里原样存在、顺序一致（`labs/ch03_gradient_descent.py` 的最后一个小节是样板；找不到包时打印一句并跳过）。源码一改，实验就红。
- 结尾 `done()`（打印 `✓ 全部通过`）。能用 CPU 就用 CPU；必须用 GPU 的章（14、15）另配一个 CPU 伴生实验来画图、锁手算，GPU 实验头部保留 `# LAB_REQUIRES: gpu`。
- `labs/worked_examples.py` **冻结不改**：它复核的就是各章的手算数字，章节实验里再 `check` 一遍同样的数。

## 10. 章末四块

**📍 映射到项目**

```text
## 📍 映射到项目
```
