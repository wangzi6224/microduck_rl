## 2.0 先看地图：这些名字都在描述“数怎么组织”

**一个数叫标量；有顺序的一串数叫向量；按行列排成的数表叫矩阵。在本书的机器学习代码里，它们都可以用张量来存。**

先想象你在给机器人做记录：只记一个分数，用一个数就够；记前后、左右速度，就要两个数；
记录三只机器人，就把三份清单排成表；连续记录两个时刻，就需要两页表。

![从一个数、一串数、一张表，到两页表；每多一种查找条件，就多一条数据轴](../figures/ch02_number_to_tensor.png)

**读图顺序：先看数怎样摆，再看找到其中一个数需要回答几个问题。**

| 记录方式 | 找到一个数，要回答什么问题？ | 数据有几条轴？ |
|---|---|---:|
| 一个分数 `7` | 不用挑，就这一个 | 0 |
| 速度清单 `[3, 4]` | 第几项？ | 1 |
| 三只机器人的速度表 | 第几只机器人、第几项？ | 2 |
| 两个时刻的速度表 | 第几个时刻、第几只机器人、第几项？ | 3 |

**轴可以先理解成“查找一个数时，需要选择的一项”。** `shape`（读“形状”）记录每项有多少种选择，
例如 `(2, 3, 2)` 就是“2 个时刻、3 只机器人、2 个速度项”。图上的英文先不背，2.7–2.8 节会拆开讲。

本章最容易混的两个词，先贴上标签：

- **空间坐标轴**：往哪边走，例如往右、往上。2.3–2.4 节画箭头时用它。
- **数据轴**：选择哪一类编号，例如时刻、机器人、速度项。2.7–2.8 节找数、求和时用它。

还有一个先记住的提醒：**“3 维向量”数的是清单有 3 项；“一维张量”数的是查找只需要一个编号。**
两句话可以同时成立。现在觉得别扭很正常，2.8 节会用同样三个数的三种摆法解释。

第一次读，只要按顺序看正文、图片和手算。标着“进阶”的折叠内容可以先跳过；代码是复核工具，不是阅读门槛。

## 2.1 向量：一张购物清单

去超市买：3 个苹果、2 个梨、1 个西瓜。写成一串数：**(3, 2, 1)**。
顺序有意义——第 1 位永远是苹果、第 2 位永远是梨。

在本章里，把**固定项数、顺序有意义的一串数**叫作**向量**（vector）。
单独的 `3` 是一个**标量**（scalar），整串 `(3, 2, 1)` 才是向量。
如果你会编程，可以把它存成数组；不会也不影响理解：

```js
const cart = [3, 2, 1];   // 苹果、梨、西瓜
```

说“几维向量”时，数的是**有几个分量**；“分量”就是清单里的一项。购物清单是 3 维；机器人的观测是 61 维——一张 61 项的清单，
第 1 位永远是"绕前后轴转多快"，第 7 位永远是"左髋偏航角"……第 15 章会逐项列出这张清单。

**61 维不要求你想象一个有 61 个空间方向的房间。** 在这里，它只是每次要填 61 个数字的记录单。
清单 `(0, 0, 0)` 也仍然有 3 维：填零不等于删掉那一项。

数学记号：

| 符号 | 怎么读 | 就是 |
|---|---|---|
| $\mathbf{v}$ | "向量 v" | 整张清单。正式写法加粗或加箭头 $\vec v$；本书后面偷懒不加粗，靠上下文 |
| $v_i$ | "v 下标 i" | 本章数学下标从 1 数起：$v_1$ 是第 1 项；代码从 0 数起，同一项写 `v[0]` |
| $\mathbb{R}^{61}$ | "R 的 61 次方" | "61 个实数排成一串"的全部可能。"观测 $\in \mathbb{R}^{61}$"就是"观测是 61 维向量" |

### 两张清单相加、清单翻倍

上午买了 (3, 2, 1)，下午又买了 (4, −1, 0.5)（−1 表示退了一个梨）。一共买了多少？**逐项相加**：

$$(3, 2, 1) + (4, -1, 0.5) = (7, 1, 1.5)$$

明天买双份：**每一项乘 2**：$2 × (3, 2, 1) = (6, 4, 2)$。

前端里就是 `a.map((ai, i) => ai + b[i])` 和 `a.map(ai => 2 * ai)`。减法同理。

上一章打分代码里 `command[:, :2] - actual[:, :2]` 就是两张 2 项清单相减：
(指令前后速度, 指令左右速度) − (实际前后速度, 实际左右速度) = (前后偏差, 左右偏差)。

> **停一下，自测**：(1, 2, 3) + (4, −1, 0.5) = ？
> <details><summary>答案</summary>(5, 1, 3.5)。实验第 1 节打印的就是这个。</details>

## 2.2 点积：清单 × 价格 = 总价

苹果 4 块一个、每个梨有 1 块退款抵扣、西瓜 0.5 块。为了同时练习正负数，记账清单写成 (4, −1, 0.5)。
购物清单 (1, 2, 3) 一共多少钱？**每一项数量 × 单价，再全部加起来**：

$$1×4 + 2×(-1) + 3×0.5 = 4 - 2 + 1.5 = 3.5$$

这个"对应项相乘再相加"叫**点积**（dot product），写作 $\mathbf{a}\cdot\mathbf{b}$，读"a 点 b"。
输入两张同样长的清单，输出**一个数**。

正式公式：

$$\mathbf{a}\cdot\mathbf{b} = \sum_{i=1}^{n} a_i b_i$$

这里第一次出现大 Σ（"西格玛"）。它就是一个 for 循环：

```js
let s = 0;
for (let i = 0; i < n; i++) s += a[i] * b[i];   // 这就是 Σ a_i b_i
```

| 符号 | 怎么读 | 就是 |
|---|---|---|
| $\sum_{i=1}^{n}$ | "对 i 从 1 到 n 求和" | for 循环，i 从 1 跑到 n，把后面的东西累加 |
| $a_i b_i$ | | 第 i 项相乘 |

numpy 里写 `a @ b`。实验第 1 节手算和 numpy 都得 3.5。

**为什么重要**：神经网络里每一个"神经元"做的第一件事，就是拿自己的一张"价格表"（权重）和输入清单算一次点积
（第 6 章）。总价高 = "这个输入长得像我在找的东西"。

<details>
<summary>进阶：点积的几何意义（现在可跳过）</summary>

$\mathbf{a}\cdot\mathbf{b} = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta$，θ 是两个向量的夹角。
同向时 cos θ = 1 点积最大，垂直时为 0，反向为负。所以点积衡量"两个方向多一致"。
实验算出 (1,2,3) 和 (4,−1,0.5) 夹角 77°，接近垂直，所以 3.5 相对它们的长度不算大。
第 3 章讲"梯度方向涨得最快"时会用到这一条。
</details>

## 2.3 长度：先画懂坐标轴，再量箭头

### 坐标轴就是两把标好正负方向的尺子

在方格纸上，画一把横尺和一把竖尺，让它们的 0 对齐。交点叫**原点**，就是起点 `(0, 0)`。
横尺起名 **x 轴**，本图约定向右为正、向左为负；竖尺起名 **y 轴**，向上为正、向下为负。
字母只是名字，不是新的计算。

现在约定清单的顺序是 **`(横着走多少, 竖着走多少)`**。那么 `(3, 4)` 就是从原点向右 3 格、向上 4 格。
连接起点和终点的箭头，表示这次总的移动。坐标写的是两个方向各占多少，箭头长度才是直线距离。

![从原点向右三格、向上四格，终点是(3,4)，直线箭头长度是5](../figures/ch02_vector_coordinates.png)

**这样读图：** 先沿横尺走 3 格，再向上走 4 格，最后看连接两端的斜箭头。
`(−3, 4)` 会落在左上方；`(3, −4)` 会落在右下方。负号告诉你方向相反。

购物清单和箭头为什么都叫向量？在这里我们用一串有顺序的数表示它们。
当每一项代表空间中沿某根坐标轴的位移时，这串数就能画成箭头；苹果、梨、西瓜的数量则不必解释成物理位移。

### “有几项”和“箭头多长”是两个问题

上图绕着直角走的路是 `3 + 4 = 7` 格，斜箭头却只长 **5** 格。
勾股定理给直角三角形一条规则：**两条直角边各自平方，再相加，等于斜边的平方。**

`3²` 读“三的平方”，就是 `3 × 3 = 9`；`4² = 16`，所以斜边的平方是 `9 + 16 = 25`。
“开平方根”就是反问“哪个非负数乘自己等于 25？”答案是 5，写作 $\sqrt{25}=5$。

所以向量 `(3, 4)` **有 2 个分量，是 2 维向量；它画成的箭头长度是 5。** 别把这两个数混为一谈。

三维、61 维一样：**每一项平方，加起来，开根号**。这叫向量的**长度**，这里使用的正式名字是**欧几里得范数**（norm），写作 $\|\mathbf{v}\|$：

$$\|\mathbf{v}\| = \sqrt{v_1^2 + v_2^2 + \cdots + v_n^2}$$

实验：$\|(1, 2, 3)\| = \sqrt{1 + 4 + 9} = \sqrt{14} = 3.74$。

代码里更常见的是**长度的平方** $\|\mathbf{v}\|^2 = v_1^2 + \cdots + v_n^2$——不开根号，省事，也没有根号带来的求导麻烦。

**现在把上一章的打分公式说准确。** 偏差是 2 维向量（前后偏差，左右偏差）。
代码 `torch.sum(torch.square(...))` 算的是"每项平方再加起来"= **偏差向量的长度平方**。所以

$$\text{分数} = \exp\!\left(-\frac{\|\mathbf{偏差}\|^2}{\sigma^2}\right)$$

上一章的一维版本只是它的特例。"偏差多大"在多维里的意思就是"偏差向量多长"。

**单位向量**：长度恰好为 1 的向量，只保留"方向"。任何非零向量除以自己的长度就变成单位向量（零向量不能除以长度 0）：
(1, 2, 3)/3.74 = (0.27, 0.53, 0.80)。下一节马上用到。

## 2.4 手机的重力感应：项目里的第一个真实向量

> 这一节是“向量能干什么”的应用故事。第一遍读懂“重力没动、身体上的尺子转了”即可；
> 后面的三角函数推导放在折叠块里，可以学完矩阵和张量再回来。

手机里有个重力传感器。手机平放桌上，它读到"重力朝下"；把手机竖起来，它读到"重力朝手机的底边"——
所以手机知道该横屏还是竖屏。**重力没变，变的是手机自己的姿势。**

再说得直白一点：这个传感器**不会**告诉你"世界的下在哪"（那永远是同一个方向，不用问）。
它告诉你的是：**"从我自己的身体看，下在哪一边。"** 手机躺着，"下"在它的背面；手机立着，"下"在它的底边。
读数变了，是因为"我"转了。

机器人也需要知道这种方向信息。这里讲的是估计或仿真得到的重力方向，不是把加速度计的原始读数直接当重力。
观测 61 项里第 4–6 项叫 `projected_gravity`（投影重力）：
**从机器人自己的角度看，重力指向哪个方向**，用一个 3 维单位向量表示（长度恒为 1，只表示方向，就是 2.3 节最后那个"单位向量"）。

这里约定身体 **x 轴朝前、y 轴朝左、z 轴朝上**。轴像绑在身体上的三把尺子：身体转，它们一起转。
世界坐标系则像固定在房间里的尺子。**同一个箭头，换一套尺子量，三个读数就可能改变。**
三维的“前、左、上”和 2.3 节平面图的“右、上”是不同场景的标记，先看约定再读字母。

![投影重力：重力没变，变的是姿势](../figures/ch02_projected_gravity.png)

### 怎么读上面这张图

先只看上面一排的三张小图，它们是同一个机器人的三种姿势（站直、前倾 30°、前倾 70°）。每张图里有四样东西：

| 图里的东西 | 是什么 | 三张图之间变不变 |
|---|---|---|
| 黑色粗箭头「重力 g」 | 世界的"下"。永远竖直向下，长度永远是 1 | **完全不变** |
| 蓝色细箭头「机身"上"」 | 机器人自己的上下轴，钉在身上 | 跟着身体一起转 |
| 绿色细箭头「机身"前"」 | 机器人自己的前后轴，钉在身上 | 跟着身体一起转 |
| 蓝色粗短段、绿色粗短段 | 把黑箭头**拆**到那两根轴上，各占多少 | 姿势一变就变 |

那两段粗线的长度（带正负号），就是传感器报给策略网络的两个数：沿"机身上"轴的那段是 $g_z$，沿"机身前"轴的那段是 $g_x$。
虚线画出的那个平行四边形只是在说一件事：**绿段 + 蓝段 = 黑箭头**，一点没多、一点没少。

三张图连起来看就是全部故事：

1. **站直**：黑箭头正好压在"机身上"轴上，全部重力都落进 $g_z$ 这一项，$g_z=-1$，而 $g_x=0$。
2. **前倾 30°**：身体转了，黑箭头没转，于是它开始"斜着"压在两根轴上——$g_x$ 从 0 变成 0.50，$g_z$ 从 −1 缩到 −0.87。
3. **前倾 70°**：大部分重力都跑到"前后"那一项去了，$g_x=0.94$，$g_z$ 只剩 −0.34。仓库就是在这里判定"摔倒"。

在图示的 **0° 到 90° 纯前倾**范围内，$g_x$ 从 0 增到 1，$g_z$ 从 −1 增到 0。
左右歪要看 $g_y$，不能只凭 $g_x$ 判断所有方向的倾斜。

<details>
<summary>进阶手算：前倾 30° 时，0.50 和 −0.87 是怎么算出来的？</summary>

### 这两个数怎么算出来——就是 2.2 节的点积

"把一个箭头拆到某根轴上占多少"，数学上就是**和那根轴的单位向量做一次点积**：

$$g_x = \mathbf{g}\cdot\hat{\mathbf{x}}_{\text{机身前}}, \qquad g_z = \mathbf{g}\cdot\hat{\mathbf{z}}_{\text{机身上}}$$

下面这张图把前倾 30° 这一种情况从头到尾算了一遍（为了看得清，画的是侧视的二维截面：**画布向右 = 机器人的前，画布向上 = 天**）。

![两根身体轴的坐标是怎么来的](../figures/ch02_axis_rotation.png)

#### ① 先看站直：两根轴就是坐标纸的两个方向

括号里两个数的约定先说死：**(往右伸多少, 往上伸多少)**。站直时

- 机身"上"轴笔直朝天 → $(0,\,1)$，一点不往右
- 机身"前"轴水平朝前 → $(1,\,0)$，一点不往上

这两根轴有三条性质，后面一直成立：**长度恒为 1**、**互相垂直 90°**、**钉死在身体上**（身体转多少，它俩就跟着转多少）。

#### ② 机身"上"轴转 30° 后 = (sin30°, cos30°)

身体前倾 30°，这根原本朝天的箭头就**从竖直方向歪开了 30°**。图里那个直角三角形把它拆开：

- 斜边 = 箭头本身，长度还是 **1**（转动不改变长度）
- 竖直那条直角边 = $\cos 30° = 0.87$
- 水平那条直角边 = $\sin 30° = 0.50$

$$\text{机身"上"} = (\sin 30°,\ \cos 30°) = (0.50,\ 0.87)$$

这不是新公式，就是 sin / cos 的定义本身：**一根长度为 1、从竖直方向歪开 θ 的箭头，水平占 $\sin\theta$、竖直占 $\cos\theta$**（下一小节"补课"专门讲）。

> **直觉检查**：才歪 30° 不算多，所以它应该"主要还朝上、稍微朝前"。0.87 > 0.50 ✓。
> 歪到 90°（趴平）时就变成 $(1,\,0)$——全朝前、一点不朝上。

#### ③ 机身"前"轴转 30° 后 = (cos30°, −sin30°)

同一次转动，这根原本水平朝前的箭头**鼻子朝下低了 30°**。它离水平只差 30°，所以三角形里两条边换了个位置：

- 水平那条 = $\cos 30° = 0.87$（还是主要朝前）
- 竖直那条 = $-\sin 30° = -0.50$，**负号就是"朝下"**

$$\text{机身"前"} = (\cos 30°,\ -\sin 30°) = (0.87,\ -0.50)$$

**为什么两个数像是"换了个位置"？** 因为两根轴永远差 90°。一根从竖直量起是 30°，另一根从水平量起就也是 30°，而 sin 和 cos 正好是一对互换的函数（$\sin 30° = \cos 60°$）。所以一根写成 $(\sin,\cos)$，另一根就写成 $(\cos,-\sin)$：数字对调，再给"低头"那一份加负号。

#### ④ 拿这两根轴去拆重力：各做一次点积

万事俱备。重力在这张图里是 $\mathbf{g}=(0,\,-1)$（不往右、往下 1）。按 2.2 节"对应项相乘再相加"：

$$g_z = \mathbf{g}\cdot\text{机身"上"} = 0×0.50 + (-1)×0.87 = -0.87$$

$$g_x = \mathbf{g}\cdot\text{机身"前"} = 0×0.87 + (-1)×(-0.50) = +0.50$$

第一个式子里**第一项直接是 0**，因为重力没有水平成分；剩下的就是 $-1$ 乘那根轴的竖直分量。
第二个式子里出现**负负得正**：重力朝下是 $-1$，"前"轴也朝下低了头（$-0.50$），两个"朝下"一乘就成了正的 $+0.50$——这正是"前倾时 $g_x$ 为正"的来源。

和上一张大图里标的 $(+0.50,\ 0,\ -0.87)$ 一模一样。**所以这一节其实没有新东西——只是 2.2 节的点积换了个场景。**

> **两个可以随手验的自检**（图里右下角也写了）：
> - 两根轴垂直：$0.50×0.87 + 0.87×(-0.50) = 0$。点积为 0 = 两个方向垂直（2.2 节那个折叠的"进阶"）。
> - 读数还是单位向量：保留两位小数时 $0.50^2 + 0.87^2 = 1.0069 \approx 1$；使用未四舍五入的值时平方和等于 1。

它的**第一列**是转动后的机身“前”轴，**第二列**是转动后的机身“上”轴，都是用世界的尺子量的。

=\begin{pmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{pmatrix}
\begin{pmatrix}0\\-1\end{pmatrix}

## 2.5 矩阵：两家店的价格表

一家店的价格是一张清单。两家店呢？一张**表**：

|  | 苹果 | 梨 | 西瓜 |
|---|---|---|---|
| 店 A | 1 | 0 | 2 |
| 店 B | 0.5 | −1 | 1 |

这张数表就是**矩阵**（matrix）。**一横排叫一行，一竖排叫一列。**
它有 2 行 3 列，形状记作 $2 \times 3$，读“2 行 3 列”。**先说行数，再说列数**。
当它表示形状时，`2 × 3` 不是让你把表变成数字 6；只有问“一共有几格”时，才算 `2 × 3 = 6`。

$$W = \begin{pmatrix} 1 & 0 & 2 \\ 0.5 & -1 & 1 \end{pmatrix}$$

| 符号 | 怎么读 | 就是 |
|---|---|---|
| $W$ | | 矩阵习惯用大写字母 |
| $W_{ij}$ | "W 下标 i j" | 第 i 行第 j 列那一格；本章 $W_{12}$ 对应代码 `W[0, 1]`（第 1 行第 2 列） |
| $m \times n$ | "m 乘 n" | m 行 n 列。**先行后列**，最容易记反的地方 |

### 矩阵乘向量 = 每家店各算一次总价

购物清单 (1, 2, 3)，在每家店各花多少钱？**每一行和清单做一次点积**：

- 店 A：1×1 + 0×2 + 2×3 = 7
- 店 B：0.5×1 + (−1)×2 + 1×3 = 1.5

结果是一张新清单 (7, 1.5)——"在每家店的花费"。写作 $W\mathbf{x}$，读"W 乘 x"：

$$(W\mathbf{x})_i = \sum_{j} W_{ij}\, x_j \qquad\text{（第 i 个输出 = 第 i 行 与 x 的点积）}$$

实验第 3 节：`W @ x = [7, 1.5]`，和逐行点积一致。

![同一份购物清单分别与两行价格配对相乘，每行相加得到一个总价：7和1.5](../figures/ch02_matrix_recipe.png)

**这样读图：** 先只看店 A，把三对数相乘再相加得到 7；再用**同一份清单**算店 B，得到 1.5。
输入的三项是三种商品，输出的两项是两家店的账单，所以矩阵能把“3 个输入”变成“2 个输出”。
这里的 `@` 表示矩阵乘法；`*` 在 NumPy / PyTorch 数组里通常是逐项相乘，两者不能混用。

前端里就是一个 `map` 套一个 `reduce`：

```js
const y = W.map(row => row.reduce((s, wij, j) => s + wij * x[j], 0));
```

GPU 擅长的正是同时算几百个这样的 reduce。

### 形状规则不用背：它就是"点积要等长"

把清单换成 4 样东西 (1, 2, 3, 4) 试试：店 A 那行只标了 3 个价格（因为 $W$ 只有 3 列），
第 4 样东西**没有标价**。`1×1 + 0×2 + 2×3 + ?×4`——这个点积根本**写不出来**。
不是"规定不许算"，是这句话没有意义。

所以 $(2 \times 3)$ 的表只能乘 3 项的清单，得到 2 项清单。
这里出现了两个数字，**来历完全不同**，也是最容易混在一起的地方：

| 数字 | 回答的问题 | 从哪来 | 下场 |
|---|---|---|---|
| 3 = 3 | **能不能算** | 表的**列数** 对 清单的**项数** | 这 3 项被加成 1 个数，**消失** |
| 2 | **算出几个数** | 表的**行数** | 2 家店 → 2 个总价，**留下** |

把形状并排写出来，这件事一眼可见：

$$(2\times \underline{3})\;(\underline{3}\times 1) \;\to\; 2\times 1$$

划线的内侧必须相等、而且算完就消失；外侧的 2 和 1 留下来。
缩写成口诀就是**"内侧对上，外侧留下"**——但它只是上面那张表的简写，
忘了口诀随时可以回到"点积要等长"重推一遍。

数学推导常把向量竖着写成 `3×1`。代码里也常直接用形状 `(3,)` 的一串数，
于是 `W @ x` 的形状写成 `(2, 3) @ (3,) → (2,)`。计算一样，存放格式不一样；2.8 节会并排画出来。

> ⚠️ 最常见的记反：**不是**"两边列数相同"，而是**左边的列数 = 右边的行数**。
> 卡住时就问自己一句"这两个清单一样长吗"，点积的定义会替你回答。

### 通用规则：左行 · 右列

右边如果不止一张清单，而是 $p$ 张**并排**（$p$ 列），就对每一列各做一遍上面的事：

$$(m\times n)\,(n\times p) \;\to\; (m\times p)$$

通用说法是：**左边第 $i$ 行 · 右边第 $j$ 列 → 输出的第 $(i,j)$ 格**。
本节的"每行做一次点积"只是 $p = 1$ 的特例。

别把"行 = 输出"当定律背：2.7 节一次算 4096 只机器人时，一行是
**一只机器人**，行的角色就换了（那里的进阶折叠块会把这种摆法算一遍）。
记"左行 · 右列"、再写一遍形状，永远不会错。

## 2.6 一层神经网络 = 一张 512 行 61 列的价格表

现在可以说清"网络第一层把 61 个数变成 512 个"是什么意思了：

- 输入清单 $\mathbf{x}$：61 项（观测）。
- 一张 $512 \times 61$ 的价格表 $W$：512 家"店"，每家对 61 项各有一个价。
- 输出：512 项——"在每家店的总价"。

再给每家店加一个固定运费 $\mathbf{b}$（512 项），就是这一层的线性计算部分（加上偏置）：

$$\mathbf{y} = W\mathbf{x} + \mathbf{b}$$

后面通常还会接一个“激活函数”，第 6 章再讲；这里先看清这些数怎样算出来。

| 符号 | 在网络里叫 | 形状 |
|---|---|---|
| $\mathbf{x}$ | 输入 | 61 |
| $W$ | **权重**（weight） | $512 \times 61$ |
| $\mathbf{b}$ | **偏置**（bias） | 512 |
| $\mathbf{y}$ | 输出 | 512 |

这一层有多少个"旋钮"（参数）？价格表 512 × 61 = 31,232 个，运费 512 个，**共 31,744 个**。
实验第 4 节用 `torch.nn.Linear(61, 512)` 建了真的这一层，用 numpy 手写 `W @ x + b` 算了一遍，
逐位相同，参数个数恰好 31744。第 6 章把四层全数出来。

## 2.7 数据的轴：先找到一个数，再看 `dim=` 沿哪里加

前面每个例子都只有**一只**机器人、一张清单。训练时可以让 4096 只**仿真机器人**同时跑，
代码里每个数组都因此多出一维，`.sum(dim=1)` 满屏都是。
这一节只解决一件事：**多出来的那一维是什么，`dim=` 到底在加谁。**

这里的“轴”指**数据轴**。它和 2.3 节的空间 x、y 轴有联系，但回答的问题不同：
空间轴说“箭头往哪边”，数据轴说“查找数据时改哪一个编号”。

### 从一只到三只：清单摞成表

一只机器人的速度误差是一张 2 项清单（2.1 节）：(前后误差, 左右误差)。
比如 A 是 (0.1, −0.2)：前后差了 0.1，左右差了 −0.2（2.1 节说过，偏差 = 指令 − 实际，所以有正有负）。

三只机器人就是三张这样的清单，**上下摞起来**：

|  | 前后误差 | 左右误差 |
|---|---|---|
| A | 0.1 | −0.2 |
| B | −0.3 | 0.4 |
| C | 0.1 | 0.1 |

这就是 2.5 节那张价格表的形状，只是**行的含义换了**：不再是"第几家店"，而是"第几只机器人"。

$$E=\begin{pmatrix}0.1&-0.2\\-0.3&0.4\\0.1&0.1\end{pmatrix}$$

形状记作 `[3, 2]`——先行后列，和 2.5 节完全一样的读法。

### 找数就像查座位：先定行，再定列

给机器人和速度项都编号，**代码从 0 开始数**：A、B、C 的编号是 0、1、2；前后、左右两项的编号是 0、1。

```text
                         第 1 轴：速度项编号 →
                         0 前后      1 左右
第 0 轴：机器人编号  0 A     0.1         -0.2
          ↓         1 B    -0.3          0.4
                    2 C     0.1          0.1
```

想找 B 的左右误差，就写 **`E[1, 1]`**，读成“第 1 号机器人，第 1 号速度项”，得到 `0.4`。
**方括号里的第一个位置属于第 0 轴，第二个位置属于第 1 轴。** 轴编号按位置定，不是按数值大小定。

现在固定 B 不换：`E[1, 0] → E[1, 1]`，你在改第二个编号，也就是沿**第 1 轴**取数。
固定“左右误差”不换：`E[0, 1] → E[1, 1] → E[2, 1]`，你在改第一个编号，也就是沿**第 0 轴**取数。

**所以“沿着一条轴”就是：其他编号固定，只改变这一条轴上的编号。** 后面求和也按这个规则分组。

> 顺手拆掉一个误会：代码里那个"4096×61"**不是**一个巨大的乘法答案，
> 它是一张表的**形状**：4096 行机器人，每行 61 个观测数。上面这张 `[3, 2]` 就是它的迷你版。

一张表有两个方向，每个方向叫一条**轴**（axis）：

| 轴 | 代码里的编号 | 沿着它走，变的是 | 有多长 |
|---|---|---|---|
| 行的方向（竖着走） | 第 **0** 轴 | 换了一只机器人 | 3 |
| 列的方向（横着走） | 第 **1** 轴 | 换了一个方向（前后 / 左右） | 2 |

编号从 0 开始，和数组下标一致（2.1 节说过：数学从 1 数起，代码从 0 数起）。

别把“第 0 轴长度是 3”读成“有 3 条轴”：**第 0 轴有 A、B、C 三个位置，整张表只有两条轴。**
“第 0 轴竖着”也是这张表的画法；有多页表时，第 0 轴可以是翻页，2.8 节马上会看到。

### 冒号表示“不只取一个，把这一段都拿来”

| 写法 | 用人话读 | 得到什么？ |
|---|---|---|
| `E[1, 1]` | B 的左右误差 | 标量 `0.4` |
| `E[1, :]` | B 的所有速度项 | 清单 `[-0.3, 0.4]`，形状 `[2]` |
| `E[:, 1]` | 所有机器人的左右误差 | 清单 `[-0.2, 0.4, 0.1]`，形状 `[3]` |
| `E[:, :2]` | 所有机器人的前两项 | 整张表，形状 `[3, 2]` |

单独的 `:` 是“全选”；`:2` 是“从开头取到编号 2 **之前**”，因此取编号 0 和 1。
`E[1]` 是 `E[1, :]` 的简写。**这解释了前面为什么写 `command[:, :2]`：每只机器人的前两个指令项。**

### 每只机器人各要一个分数，所以只能沿一条轴加

我们要的是"**每只**机器人的误差有多大"。三只机器人，就该得到**三个数**。
"误差多大"就是 2.3 节的长度平方：每项平方，再加起来。

第一步，逐格平方（负号全变正）：

|  | 前后² | 左右² |
|---|---|---|
| A | 0.01 | 0.04 |
| B | 0.09 | 0.16 |
| C | 0.01 | 0.01 |

第二步是全节的关键：**加谁？** 两种加法都能算，含义完全不同。

**① 横着加**（同一行内部，把一只机器人的两个方向合起来）：

- A：0.01 + 0.04 = **0.05**
- B：0.09 + 0.16 = **0.25**
- C：0.01 + 0.01 = **0.02**

得到 3 个数，每只机器人一个。✅ 这才是我们要的。

**② 竖着加**（同一列内部，把三只机器人合起来）：

- 前后：0.01 + 0.09 + 0.01 = **0.11**
- 左右：0.04 + 0.16 + 0.01 = **0.21**

得到 2 个数："全队的前后误差合计"和"全队的左右误差合计"。
这是一个统计量，**不属于任何一只机器人**。拿它当奖励，等于让 A 为 B 的失误扣分。❌

形状自己会说话：`[3,2] → [3]` 还是 `[3,2] → [2]`，一眼就知道算的是哪一种。

### `sum(dim=...)` 指定“沿哪条轴求和”

这两种加法在 PyTorch 里分别写成 `sum(dim=1)` 和 `sum(dim=0)`。最容易记反的就是这里：

> **在 `sum` 里，`dim=` 指的是沿哪条轴合并数值。默认情况下，这条轴会从结果形状里消失。**

`sum(dim=1)` = "把第 1 轴（列的方向，两个方向）加没" → 只剩第 0 轴 → 形状 `[3,2] → [3]`。
横着加、每行得一个数，正是上面的 ①。

这条道理在 2.5 节已经见过一次：矩阵相乘时"内侧对上，算完就消失"——
被求和的那个索引不再逐项出现在结果里。这里说的是默认求和；下面会讲保留单元素轴的写法。

> **只检查形状还不够**：如果表恰好是方的（比如 2 只机器人 × 2 个方向），
> `dim=0` 和 `dim=1` 的输出**形状一模一样，两种写法都不报错**，只是意义全错——
> 训练照跑、曲线照涨，只是在奖励错的东西。
> 检查时做三件事：**给每条轴写上含义；预测输出形状；手算 A 的一个结果，看有没有把 B 的数加进来。**

### `keepdim`、`dim=-1` 和不写 `dim`，各是什么意思？

对上面**已平方**的表 `sq`，把结果放在一起比较：

| 写法 | 结果 | 形状 | 在做什么？ |
|---|---|---|---|
| `sq.sum(dim=1)` | `[0.05, 0.25, 0.02]` | `[3]` | 每只机器人合成一个数 |
| `sq.sum(dim=1, keepdim=True)` | `[[0.05], [0.25], [0.02]]` | `[3, 1]` | 同样的三个结果，保留一列的格式 |
| `sq.sum(dim=0)` | `[0.11, 0.21]` | `[2]` | 每个方向跨机器人合计 |
| `sq.sum()` | `0.32` | `[]`，也简记为 `()` | 整张表全部加成一个标量 |

`keepdim` 可以读成“保留这个轴的位置”：**原来这一轴有 2 项，现在合成 1 项，而不是把轴删掉。**
本章实验用 `tuple(t.shape)` 打印形状，所以标量显示为 `()`；PyTorch 直接打印 `t.shape` 时会显示 `torch.Size([])`，意思相同。
`dim=-1` 则表示**最后一条轴**，这张两轴表里等同 `dim=1`；如果有三条轴，就等同 `dim=2`。
这两个选项不改变“哪些数相加”的判断方法。接口规则见 [PyTorch 2.9 的 sum 文档](https://docs.pytorch.org/docs/2.9/generated/torch.sum.html)。

### 接上第 1 章：从平方和到奖励

把上面两步接上第 1 章的钟形打分，就是项目里一条真实的奖励。
整段做的事是：**逐格平方 → 每只机器人自己加起来 → 各自换算成分数。**

```python
err       = ...                           # [3, 2]  三只机器人 ×（前后, 左右）误差
sq        = err.square()                  # [3, 2]  逐格平方，形状不变，负号变正
per_robot = sq.sum(dim=1)                 # [3]     把"方向"这条轴加没 → 每只一个误差
reward    = torch.exp(-per_robot / 0.1)   # [3]     第 1 章的 exp(−偏差²/σ²)，这里 σ² = 0.1
# per_robot = [0.05, 0.25, 0.02]
# reward   ≈ [0.606531, 0.082085, 0.818731]
```

形状一路是 `[3,2] → [3,2] → [3] → [3]`：**进来三只，出去三个分数**，中间一步也没混。
C 的误差最小（0.02），分数最高（0.82）；B 最大（0.25），只剩 0.08——就是第 1 章那条钟形曲线。

现在回头看第 1 章末尾那行"看不懂也没关系"的代码：

```python
xy_error = torch.sum(torch.square(command[:, :2] - actual[:, :2]), dim=1)
```

每个符号现在都认识了：`command[:, :2] - actual[:, :2]` 是两张 `[4096, 2]` 的表相减（2.1 节），
`square` 逐格平方，`dim=1` 把"前后/左右"这条轴加没，得到 `[4096]`——**每只机器人一个偏差²**。

<details>
<summary>进阶：转置与广播——批量为什么写成 $XW^\top$（现在可跳过）</summary>

2.5 节算 $W\mathbf{x}$ 时，输入是**竖着的一列**。但上面的批量表里，**一只机器人是一行**。
同一件事，输入的摆法变了，公式就得跟着变。

$$X=\begin{pmatrix}1&2\\3&4\end{pmatrix},\qquad
W=\begin{pmatrix}2&0\\1&-1\\0&3\end{pmatrix}$$

$X$ 是 2 行 2 列：两只机器人，每只 2 项输入。$W$ 是 3 行 2 列：3 个输出，每个对 2 项输入各有一个权重。

直接写 $WX$ 形状也能对上（$(3\times\underline{2})(\underline{2}\times2)\to3\times2$），
但那是把 $X$ 的**列**当成输入——和"一行一只机器人"的摆法对不上。
要让 $X$ 的**行**当输入，就把 $W$ 转置过来放右边：$XW^\top$，
形状 $(2\times\underline{2})(\underline{2}\times3)\to 2\times3$。
$\top$ 是**转置**，把 $W$ 从 3×2 翻成 2×3（2.6 节折叠块里提过）。

代进数字，按 2.5 节的"左行 · 右列"算：

- 第一行输入 `[1, 2]` → `[2, −1, 6]`
- 第二行输入 `[3, 4]` → `[6, −1, 12]`

输出形状 `[2, 3]`：两只机器人，每只三个输出——行仍然是"第几只机器人"，没变。

再加偏置 `[0.5, 0, −1]`（2.6 节那笔"运费"）：**每一行都加同一份运费**，
得到 `[2.5, −1, 5]` 和 `[6.5, −1, 11]`。这叫**广播**（broadcast）：
可以理解成每一行都使用同一份偏置，实际计算不必真的复制出很多份。不是两只机器人共用了一条观测，是它们交了同样的运费。

最后区分两个长得很像的运算：`X * X` 是**逐格相乘**（`[[1,4],[9,16]]`，形状不变），
`X @ W.T` 才是矩阵乘法（会把一条轴加掉）。分不清时，先写形状，再代一行数字。

</details>

## 2.8 维度与张量：几条轴、每条多长、总共几个数？

### 张量是这些数据的共同存放方式

在本书的 **NumPy / PyTorch 数组语境**里，可以先把张量（tensor）理解为“按形状组织的一组数”。
标量可以存成零维张量，向量可以存成一维张量，矩阵可以存成二维张量；更多轴也照样能存。
**不是到三维才叫张量，也不是张量里的数字特别复杂。**

严格数学、物理里“张量”还有更完整的定义；本章只讲读懂训练代码所需的数组含义。
在 PyTorch 中这些数据使用 `Tensor` 类型表示，见 [官方 Tensor 文档](https://docs.pytorch.org/docs/2.9/tensors.html)。

### 一个“维”字，问的可能是不同的问题

拿 `[3, 4, 5]` 举例：

- 问“这是**几维向量**？”——有三个分量，所以是 **3 维向量**。
- 问“存它的数组有**几条轴**？”——用一个编号就能取数，所以是 **1 维张量**。
- 问“这条轴**多长**？”——可选编号 0、1、2，所以长度是 **3**。

![同样三个数，一串数形状(3,)、一行矩阵形状(1,3)、一列矩阵形状(3,1)；数字没变，轴数和地址格式可以变](../figures/ch02_vector_shapes.png)

**这样读图：** 看第一幅，取 `4` 只需选位置 1；看第二幅，要选“行 0、列 1”；
看第三幅，要选“行 1、列 0”。后两幅都有“行、列”两条轴，即使其中一条轴只有一个位置。

| 数据 | 数组形状 `shape` | 轴数 `ndim` | 元素总数 `numel()` |
|---|---|---:|---:|
| `7` | `()` | 0 | 1 |
| `[7]` | `(1,)` | 1 | 1 |
| `[3, 4, 5]` | `(3,)` | 1 | 3 |
| `[[3, 4, 5]]` | `(1, 3)` | 2 | 3 |
| `[[3], [4], [5]]` | `(3, 1)` | 2 | 3 |
| 三只机器人，每只两个数 | `(3, 2)` | 2 | 6 |

这三个代码名字可以分别读成：**`shape` = 每条轴多长；`ndim` = 有几条轴；`numel()` = 一共有几个数。**
`()` 表示形状中没有轴，但标量仍然有一个值，不是空数据。
`(3,)` 的逗号是 Python 写“只有一项的形状”时的格式，**不表示后面漏了一个数**。
正文形状简写 `[3, 2]` 和代码打印 `(3, 2)` 说的是同一件事；要结合上下文区分“这是形状”还是“这是数据”。

记住一个具体结论就够了：**一条 61 维观测，可以存成 `shape=(61,)`、`ndim=1` 的张量。**
再把 4096 条观测摆成表，才得到 `shape=(4096, 61)`、`ndim=2`。61 没变，记录的条数变了。

不要用“数值是不是 0”“总共有几个数字”“画在纸上横着还是竖着”猜轴数。
也暂时不用 `rank` 这个词来代替轴数：它还可能指**矩阵的秩**，那是另一个概念。

### 第三条轴：给记录增加一个“时刻”

先用很小的数据：两个时刻、三只机器人、每只两项速度。
为了让你一眼认出每格在哪，下面用 **1 到 12 的教学构造数字**，不是实测速度。

```python
T = torch.tensor([
    [[1, 2], [3, 4], [5, 6]],       # 时刻 0：第一张表
    [[7, 8], [9, 10], [11, 12]],    # 时刻 1：第二张表
])
# shape = (2, 3, 2)
#          时刻  机器人  速度项
```

![两张完整展开的速度表：选择时刻1、机器人2、速度项0，就找到11](../figures/ch02_tensor_address.png)

**手指跟着图走一遍：** 先翻到编号 1 的那页，找到编号 2 的机器人，再取编号 0 的速度项，得到 **11**。
写成代码就是 `T[1, 2, 0]`。这串编号是地址，**不是 1 × 2 × 0 的算式**。

| 轴编号 | 标签 | 沿着这条轴走，换什么？ | 长度 |
|---|---|---|---:|
| 0 | 时刻 | 翻到另一个时刻的整张表 | 2 |
| 1 | 机器人 | 在一页内换机器人 | 3 |
| 2 | 速度项 | 同一只机器人的前后 / 左右项 | 2 |

形状 `(2, 3, 2)` 有 **3 条轴**，一共 **2 × 3 × 2 = 12 个数**。
两条轴长度都等于 2，只是碰巧；它们分别代表时刻和速度项，含义不同。
**三轴张量不等于三维空间里的物体。** 这里新增加的是时间轴；为方便翻页，我们把它放在第 0 轴，
于是总共有三条轴。不用想象一个立方体。

### 取一页、取一行，剩下的形状怎么读？

先选定一个编号，相当于这个问题已经回答完，后面只需回答剩下的问题：

| 取法 | 得到什么？ | 形状 |
|---|---|---|
| `T[1]` | 时刻 1 的整张表 `[[7,8],[9,10],[11,12]]` | `(3, 2)` |
| `T[1, 2]` | 该时刻机器人 2 的两个数 `[11,12]` | `(2,)` |
| `T[1, 2, 0]` | 一个数 `11` | `()` |
| `T[:, 2, :]` | 机器人 2 在两个时刻的记录 `[[5,6],[11,12]]` | `(2, 2)` |

还有个小区别：`T[1:2]` 用的是“一段范围”，保留“页”这个位置，形状是 `(1, 3, 2)`；
`T[1]` 直接选定一页，形状是 `(3, 2)`。数字相同，包装不同，和前面的“一串数 / 一行表”是同一个道理。

### 三条轴上的求和，不用发明新规则

仍然是：**固定其他编号，只沿指定轴取数相加。** 这次对 T 的原始数字直接求和，不先平方：

| 写法 | 举一个手算 | 剩下哪些标签？ | 输出形状 |
|---|---|---|---|
| `T.sum(dim=2)` | 时刻 1、机器人 2：`11 + 12 = 23` | 时刻、机器人 | `(2, 3)` |
| `T.sum(dim=1)` | 时刻 1、前后项：`7 + 9 + 11 = 27` | 时刻、速度项 | `(2, 2)` |
| `T.sum(dim=0)` | 机器人 2、前后项：`5 + 11 = 16` | 机器人、速度项 | `(3, 2)` |

每一种都能算，只是回答不同的问题。要不要把两个时刻的速度相加，取决于你的目的，不能仅凭“代码能运行”判断。
这里 `dim=-1` 等同 `dim=2`；加上 `keepdim=True`，`(2, 3, 2)` 就变成 `(2, 3, 1)`。
**不要背“最后一轴永远是特征”**：如果数据换一种排列，轴标签和 `dim` 就得跟着换。

### 现在再看项目里的 `[24, 4096, 61]`

它只是把上面的小例子放大：**24 个采样时刻，每个时刻 4096 只仿真机器人，每只 61 项观测。**
在这种排列下，第 0 轴是时间、第 1 轴是环境（机器人）、第 2 轴是观测项。
“批量”（batch）表示把多份数据放在一起处理；它不自动规定哪条轴永远是第 0 轴。

数据能分清来自谁，是因为计算保留了这些标签所对应的位置：例如对最后一轴求和，会得到
`[24, 4096]`，每个时刻、每只机器人都有自己的结果，而不是把所有机器人加在一起。

同一回合里，**时间有先后因果**：下一步状态是执行这一步动作后的结果。
**机器人编号没有这种因果**：B 不是 A 的下一时刻。
第 12 章的 GAE 沿时间递推，还要处理回合结束，不能把 A、B 两只机器人的经历误接成一条。
轴不会自动替你理解含义；标对位置、用对运算，数据才不会被错误地混起来。

## 本章小结

- **向量** = 购物清单，定长、顺序有意义。观测是 61 项的清单。加法逐项加，翻倍逐项乘。
- **点积** = 清单 × 价格表 = 总价，$\sum a_i b_i$，Σ 就是 for 循环。
- **长度** $\|\mathbf{v}\| = \sqrt{\sum v_i^2}$，勾股定理；代码里常用长度的平方。上一章的"偏差²"其实是偏差向量的长度平方。
- **投影重力**：从机器人自己看重力指哪；把重力这个箭头拆到两根身体轴上，拆出来的两个数就是点积。
  前后左右分量的平方和 = 站直打分的偏差²；上下分量 $g_z$ 管"倒没倒"。
- **矩阵** = 多家店的价格表，$m\times n$ 先行后列；**矩阵乘向量** = 每行各算一次总价。
  形状能对上不是规定，是因为点积要等长：**左边的列数 = 右边的行数**（内侧对上，外侧留下）。
- 一层网络 $\mathbf{y} = W\mathbf{x} + \mathbf{b}$：第一层 512×61 的表 + 512 个运费 = 31,744 个旋钮。
- **空间坐标轴**告诉你箭头往哪边；**数据轴**告诉你取数时在选哪一类编号。空间里的三个分量可以存成一串数。
- **维度要问清在数什么**：3 维向量有 3 个分量；存成形状 `(3,)` 时只有 1 条数据轴。
  `shape` 是各轴长度，`ndim` 是轴数，`numel()` 是元素总数。
- **求和**先固定其他编号，再沿 `dim=k` 指定的轴相加。默认删掉该轴；`keepdim=True` 则把该轴长度变为 1。
  写出形状、给轴贴标签，再手算一项，才能核对意义。
- **张量**在本章是带形状的数组，标量、向量、矩阵都可以这样存。`[24, 4096, 61]` 的标签是时间、机器人、观测项；
  机器人编号不是时间顺序，计算时不能误接。
