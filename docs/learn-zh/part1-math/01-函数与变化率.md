## 1.1 函数：一台机器，喂进去一个数，吐出来一个数

先不谈数学。想象一台自动售货机：投 5 块钱，掉出一瓶水。投同样的钱，永远掉同样的东西。
它不会今天掉水、明天掉可乐。

**函数**就是这样一台"确定的机器"：给它一个输入，它按固定规则给你一个输出。
同一个输入，永远得到同一个输出。

如果你写前端，你天天在写函数：

```js
const double = (x) => x * 2;   // 喂 3，吐 6，永远
const square = (x) => x * x;   // 喂 3，吐 9，永远
```

数学里给 `square` 起个名字叫 $f$，写成

$$f(x) = x^2$$

读作："f 在 x 处的值，等于 x 的平方"。就三个符号：

| 符号 | 怎么读 | 就是 |
|---|---|---|
| $f$ | "f" | 机器的名字。和变量名一样，随便起，惯用 f、g、h |
| $x$ | "x" | 喂进去的数 |
| $f(x)$ | "f of x" | 吐出来的数 |

代几个数试试：$f(3) = 9$，$f(-2) = 4$，$f(0.5) = 0.25$，$f(0) = 0$。

### 把函数画出来

把一堆"喂了什么、吐了什么"记成表：

| 喂 x | 吐 f(x) |
|---|---|
| -2 | 4 |
| -1 | 1 |
| 0 | 0 |
| 1 | 1 |
| 2 | 4 |
| 3 | 9 |

横轴放 x，纵轴放 f(x)，每一行是一个点，连起来就是**函数的图像**。
$f(x)=x^2$ 画出来是一个 U 形（抛物线），最低点在 x = 0。

> **停一下，自测**：$f(x) = x^2$，$f(4)$ 是多少？$f(-4)$ 呢？
> <details><summary>答案</summary>都是 16。负数平方也是正数，所以图像左右对称。</details>

### 这和机器人有什么关系

后面你会反复遇到三台"机器"，它们都是函数，只是喂的东西不一定是一个数：

| 这台机器 | 喂进去 | 吐出来 |
|---|---|---|
| **打分规则**（奖励函数） | 机器人现在的状态 | 一个分数 |
| **策略**（神经网络） | 61 个数 | 14 个数 |
| **损失函数** | 网络的全部参数 | 一个数："现在有多差" |

"喂 61 个数"怎么处理，第 2 章讲。现在只要记住：**函数 = 确定的输入→输出机器**。
这里讨论的是确定的输入输出关系。代码里的 `def` 若读取随机数、时间或外部状态，不能只凭显式参数就保证同样输出；需要把那些影响也计入输入。

## 1.2 变化率：东西变得有多快

开车从 A 到 B，100 公里，用了 2 小时。你会说"平均速度 50 公里/小时"。你是这么算的：

$$\text{平均速度} = \frac{\text{走了多远}}{\text{用了多久}} = \frac{100}{2} = 50$$

这个"多远 ÷ 多久"就是**变化率**：位置变了多少，除以时间变了多少。

现在换成函数的语言。有一条直线 $y = 2x + 1$：

| x | y = 2x+1 |
|---|---|
| 0 | 1 |
| 1 | 3 |
| 2 | 5 |
| 3 | 7 |
| 4 | 9 |

x 每加 1，y 就加 2。"y 变了多少 ÷ x 变了多少" = 2/1 = 2。随便挑两行：从 x=1 到 x=4，y 从 3 到 9，
(9−3)/(4−1) = 6/3 = 2。还是 2。

这个数叫**斜率**（slope）。直线的斜率处处一样——直线就是"匀速"的。

数学上用一个符号表示"变了多少"：希腊字母 Δ（读"德尔塔"）。$\Delta x$ 就是"x 的变化量"，
$\Delta y$ 是"y 的变化量"。斜率写成：

$$\text{斜率} = \frac{\Delta y}{\Delta x}$$

读作"德尔塔 y 比德尔塔 x"。**只是"多远除以多久"换了身衣服**，没有新东西。

## 1.3 曲线上的"速度"：导数

直线好办。可是 $f(x) = x^2$ 是弯的。弯的线，斜率处处不同——就像一辆一直在加速的车，
你问"它的速度是多少"，得先说"在哪个瞬间"。

那怎么算"在 x = 3 这一个点上，f 变得有多快"？

办法很朴素：**从 3 出发，往前走一小步，看平均变化率；然后把这一步缩短，再缩短，看结果往哪个数靠。**

把"一小步"叫 h。从 3 走到 3+h：

$$\text{平均变化率} = \frac{f(3+h) - f(3)}{h}$$

（分子是"f 变了多少"，分母是"x 变了多少"，还是 1.2 节的"多远除以多久"。）

实验脚本 `ch01_derivative.py` 第 1 节真的算了一遍，h 从 1 一路缩到 0.00001：

```
     h   f(3+h)  (f(3+h)-f(3))/h       与 6 的差
------  -------  ---------------  -----------
     1       16                7            1
   0.1     9.61              6.1          0.1
  0.01   9.0601             6.01         0.01
 0.001    9.006            6.001        0.001
0.0001   9.0006           6.0001       0.0001
 1e-05  9.00006          6.00001  9.99995e-06
```

看最后一列：h 每缩 10 倍，结果就离 6 近 10 倍。它在**逼近 6**，永远到不了但可以无限接近。

画出来更直观。每条虚线是"从 3 走 h 步"连成的线（叫割线），h 越小它越贴近那条蓝色的线——
在 x=3 处刚好"擦着"曲线的线（叫切线）。切线的斜率就是 6。

![割线一步步变成切线](../figures/ch01_secant_to_tangent.png)

**这个"h 缩到无限小时逼近的那个数"，就叫 f 在 x=3 处的导数**（derivative）。记作

$$f'(3) = 6$$

$f'$ 读作"f 撇"。$f'(3)$ 就是"f 在 3 这一点的瞬时变化率"。

导数本身也是一台机器：你给它一个位置 x，它告诉你那里的斜率。对 $f(x) = x^2$，
可以验证 $f'(x) = 2x$（1.5 节给规则）：$f'(3) = 6$ ✓，$f'(1) = 2$，$f'(0) = 0$（U 形的底，是平的）。

<details>
<summary>进阶：导数的正式定义（现在跳过也没关系）</summary>

上面"h 缩到无限小时逼近的数"用符号写是：

$$f'(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}$$

$\lim_{h\to0}$ 读"h 趋近 0 时的极限"，意思就是"让 h 越来越小（但不等于 0，否则除以 0），看表达式靠近哪个数"。
你在实验表格里看到的就是这个过程。

导数还有另一种写法 $\frac{dy}{dx}$，读"dy 比 dx"，把 d 想成"无限小的 Δ"。两种写法指同一个东西。
第 3 章之前你只需要认得 $f'(x)$。
</details>

> **停一下，自测**：一辆车的位置是 $s(t) = t^2$（t 秒后在 $t^2$ 米处）。它在第 3 秒的瞬时速度是多少？
> <details><summary>答案</summary>$s'(3) = 2 × 3 = 6$ 米/秒。导数就是瞬时速度。</details>

## 1.4 导数告诉你"往哪边调"

导数的正负号是全书最有用的一件事：

| 导数 | 意思 | 用人话说 |
|---|---|---|
| $f'(x) > 0$ | x 变大，f 跟着变大 | 想让 f 涨？把 x 调大 |
| $f'(x) < 0$ | x 变大，f 反而变小 | 想让 f 涨？把 x 调小 |
| $f'(x) = 0$ | 平的 | 可能到底了（或到顶了） |

再看数值大小：$|f'(x)|$ 越大，f 对 x 越敏感——调一点点就变很多。

**回到第 0 章的故事**："往得分更高的方向微调参数"，现在可以说清楚了：
在一个可以直接求导的目标函数里，导数为正可尝试把参数调大一点，为负则调小一点。
但 PPO 不直接对机器人采到的分数穿过仿真求导；它会另构造一个可求导的策略损失（1.13 节）。
第 3 章会把它推广到几十万个参数同时调，那时它叫"梯度"，但道理一模一样。

## 1.5 三条现成规则（不用每次都缩 h）

每次都算"h 缩小"太累。数学家总结了规则，本书用到的只有这几条：

| 规则 | 公式 | 例子 |
|---|---|---|
| 常数不变化 | $(c)' = 0$ | $(5)' = 0$ |
| 幂：指数搬下来，再减 1 | $(x^n)' = n\,x^{n-1}$ | $(x^2)' = 2x$，$(x^3)' = 3x^2$ |
| 常数倍照搬 | $(c \cdot f)' = c \cdot f'$ | $(5x^2)' = 10x$ |
| 加法分开求 | $(f + g)' = f' + g'$ | $(x^2 + x^3)' = 2x + 3x^2$ |

用第二条验证 1.3 节：$(x^2)' = 2x$，代 3 得 6 ✓。

## 1.6 链式法则：机器套机器

### 先看汇率

人民币换美元，汇率 0.14（1 元换 0.14 美元）。美元换欧元，汇率 0.9。
人民币直接换欧元的汇率是多少？两个相乘：0.14 × 0.9 = 0.126。

这就是链式法则的全部内容：**两台机器串起来，总的"放大倍数"等于各自倍数相乘**。

### 再看函数套函数

两台机器串成流水线：先过 $g$，输出直接喂给 $f$。

```js
const g = (x) => 2 * x + 1;     // 第一台
const f = (u) => u * u;         // 第二台
const y = (x) => f(g(x));       // 串起来：先 g 再 f
```

$y(x) = f(g(x)) = (2x+1)^2$。这叫**复合函数**（"套在一起的函数"）。

问：x 动一点，y 动多少？用汇率的思路：
- 第一台：x 动 1，$g$ 的输出 $u$ 动多少？$g'(x) = 2$（1.5 节规则）。
- 第二台：u 动 1，$f$ 的输出动多少？$f'(u) = 2u$。
- 串起来：相乘。

具体算 x = 1.5 处：
1. $u = g(1.5) = 2×1.5 + 1 = 4$
2. 第一台的倍数 $g'(1.5) = 2$
3. 第二台的倍数 $f'(u) = 2u = 2×4 = 8$
4. 总倍数 = 8 × 2 = **16**

实验第 2 节用"缩 h"的笨办法验证了：

```
 x0  数值导数  链式法则            差
---  ----  ----  -----------
1.5    16    16  4.00259e-06
```

写成公式（**链式法则**，chain rule）：

$$\big(f(g(x))\big)' = f'(g(x)) \cdot g'(x)$$

读作："套着的函数的导数 = 外层在内层输出处的导数 × 内层的导数"。就是汇率相乘。

### 为什么它是全书最重要的一条规则

神经网络就是**几十台机器串成的流水线**（第 6 章）。训练时要知道"最后的分数对最里面每一个旋钮的导数"。
办法就是：从最外层开始，一台一台把倍数乘回去。这个过程叫**反向传播**，它就是链式法则，没有别的。
你在第 7 章会看到，代码里 `loss.backward()` 这一行做的全部事情，就是你刚刚手算的那四步。

## 1.7 指数函数：一直翻倍

先看 $2^x$：$2^1 = 2$，$2^2 = 4$，$2^3 = 8$……每加 1 就翻一倍。这种"越长越快"的函数叫**指数函数**。

数学里最爱用的底不是 2，而是一个奇怪的数 $e \approx 2.718$。为什么偏偏是它？
因为 $e^x$ 有个独一无二的性质：**它的导数等于它自己**。这让它在各种公式里最省事。
（e 的来历是"连续复利"，感兴趣看折叠。）

<details>
<summary>e 从哪来</summary>
存 1 块钱，年利率 100%。一年结一次息得 2 块；半年结一次得 $1.5^2 = 2.25$；每月结一次得 $(1+1/12)^{12} \approx 2.613$；
每天结得 2.7146……结息次数无限多，逼近 2.71828…，这个数就是 e。它是"连续增长"的天然底数。
</details>

$e^x$ 在代码里写 `exp(x)`，两种写法完全一样。你在项目里主要会碰到的是**它的衰减版** $e^{-x}$：

| x | $e^{-x}$ | 说明 |
|---|---|---|
| 0 | 1 | 起点是 1 |
| 1 | 0.368 | 掉到三分之一多一点 |
| 2 | 0.135 | |
| 5 | 0.0067 | 几乎是 0 |
| 10 | 0.000045 | 很小，但不等于 0 |

要点只有两个：**从 1 开始，往 0 衰减；永远不会变成负数**。
当“某个东西”非负时，$e^{-\text{某个东西}}$ 才是一个“0 到 1 之间的分数”——正好可以当分数用。

（$e^x$ 有个逆运算叫 $\ln$，"自然对数"，问的是"e 的几次方等于这个数"。第 4 章要用到时再讲，现在跳过。）

## 1.8 钟形打分规则

### 先想一个打分办法

投飞镖。规则：正中靶心得满分 1 分，偏得越远分越低，但再离谱也不扣成负分。
你会怎么设计这条规则？

用 1.7 节的 $e^{-\text{某东西}}$ 正好：让"某东西"随着偏差变大而变大。
比如"某东西" = 偏差的平方 ÷ 一个"宽容度"：

$$\text{分数} = \exp\!\left(-\frac{\text{偏差}^2}{\sigma^2}\right)$$

逐个符号：

| 符号 | 怎么读 | 就是 |
|---|---|---|
| 偏差（代码里叫 err） | | 实际值减目标值。可正可负 |
| 偏差² | | 平方：让同样大小的正负偏差受同样评价；例如 0.1²=0.01、(−0.1)²=0.01 |
| $\sigma$ | "西格玛" | **宽容度**。σ 越大，同样的偏差扣分越少。代码里叫 `std` |
| $\sigma^2$ | "西格玛平方" | 代码里是 `std**2` |
| $-\dfrac{\text{偏差}^2}{\sigma^2}$ | | 一个 ≤ 0 的数；偏差为 0 时是 0 |
| $\exp(\cdot)$ | | 1.7 节的衰减：0 变 1，越负越接近 0 |

用项目的数字算一遍（线速度的宽容度 $\sigma^2 = 0.1$）：
- 偏差 0：$\exp(0) = 1$，满分。
- 偏差 0.1 m/s：偏差² = 0.01，0.01/0.1 = 0.1，$\exp(-0.1) = 0.905$。
- 偏差 0.3 m/s：偏差² = 0.09，0.09/0.1 = 0.9，$\exp(-0.9) = 0.407$。
- 偏差 1 m/s：偏差² = 1，1/0.1 = 10，$\exp(-10) ≈ 0$。

实验第 4 节的完整表（右边一列把分母换成 0.5，演示相同数值下曲线更宽；线速度和角速度的物理单位不同，不能直接比较谁更“宽容”）：

```
误差 err    err²  exp(-err²/0.1)  exp(-err²/0.5)
------  ------  --------------  --------------
     0       0               1               1
  0.05  0.0025         0.97531        0.995012
   0.1    0.01        0.904837        0.980199
   0.2    0.04         0.67032        0.923116
   0.3    0.09         0.40657         0.83527
   0.5    0.25        0.082085        0.606531
     1       1     4.53999e-05        0.135335
```

![同一个奖励核，std 决定多宽容](../figures/ch01_gaussian_kernel.png)

三条线是同一条公式、三个不同的 σ。σ 就是"钟有多宽"。这条曲线叫**钟形曲线**，
也叫**高斯核**（第 4 章会遇到它的孪生兄弟"高斯分布"）。
全书后面凡是看到 `exp(-something**2 / std**2)`，就是它。

## 1.9 先分清：奖励的高低，和奖励对改善的敏感程度

现在不增加新公式，只问一个新问题：**误差减少相同的一点，奖励一定增加相同的一点吗？**

想象两次速度跟踪。A 从误差 0.05 m/s 改善到 0；B 从 0.25 改善到 0.20。
两次都改善了 0.05 m/s。用本章的 $R(x)=e^{-x^2/0.1}$ 算：

| 情况 | 改善前的奖励 | 改善后的奖励 | 多拿到的分 |
|---|---:|---:|---:|
| A：0.05 → 0 | 0.975310 | 1.000000 | 0.024690 |
| B：0.25 → 0.20 | 0.535261 | 0.670320 | 0.135059 |
| C：1.00 → 0.95 | 0.000045 | 0.000120 | 0.000075 |

B 的加分约是 A 的 5.47 倍。C 的误差也减少了 0.05，但这条奖励几乎没有把改善表现出来。
这里先只比较这一项原始奖励，还没有乘权重，也没有加其他奖励。

为什么会这样？看曲线的三个位置：

- **靠近目标**：已经接近满分，顶部平，再好一点只能多拿很少分。
- **中间区域**：曲线下降得快，误差稍微缩小，奖励就明显增加。
- **离目标很远**：已经接近零分，尾部平，改善一点仍然很难拿到分。

这就是“敏感”的意思：**相同的小幅误差变化，在这里引起更大的奖励变化**。
“敏感”不等于“这里分数最高”。最高分在误差 0，中间区域的分数反而低一些。

画图时也要分清横轴。如果横轴是带正负号的偏差，完整曲线关于 0 对称；
如果横轴是非负的误差大小，看到的只是右半边：

```text
奖励
1 ──╮   目标附近：高而平
    ╰╮
     ╰╮ 中间：下降快
      ╰───── 远处：低而平
0 ───────────────────→ 误差大小
    0              越来越大
```

## 1.10 不跳步地算一次奖励的导数

为避免每行都写 `err`，暂时用 $x$ 表示带符号的偏差，用 $R$ 表示奖励。
$\sigma>0$ 是我们设好的常数，不是这次求导要改变的量：

$$R(x)=\exp\left(-\frac{x^2}{\sigma^2}\right).$$

把它拆成内外两层：

$$u(x)=-\frac{x^2}{\sigma^2},\qquad R(x)=e^{u(x)}.$$

先算内层。$1/\sigma^2$ 是固定倍数，$x^2$ 的导数是 $2x$，所以：

$$u'(x)=-\frac{1}{\sigma^2}\times 2x=-\frac{2x}{\sigma^2}.$$

再算外层：$e^u$ 对 $u$ 的导数仍是 $e^u$。按 1.6 节的链式法则相乘：

$$R'(x)=e^{u(x)}u'(x)
       =-\frac{2x}{\sigma^2}e^{-x^2/\sigma^2}
       =-\frac{2x}{\sigma^2}R(x).$$

最后这个写法最容易代数字：**先算奖励，再乘前面的系数**。
例如 $x=0.1$、$\sigma^2=0.1$：

$$R(0.1)=e^{-0.01/0.1}=e^{-0.1}\approx0.904837,$$

$$-\frac{2x}{\sigma^2}=-\frac{0.2}{0.1}=-2,$$

$$R'(0.1)=-2\times0.904837\approx-1.809675.$$

这个 −1.809675 **不是奖励值**。奖励还是 0.904837。
它描述“在这里，每增加一单位误差，奖励的局部变化率是多少”。
如果误差单位是 m/s，那么导数单位就是“奖励 / (m/s)”。

把误差从 0.100 改到 0.101，变化量 $\Delta x=0.001$。局部近似是：

$$\Delta R\approx R'(0.1)\Delta x
 =-1.809675\times0.001=-0.001810.$$

直接代公式，真正的变化约为 −0.001817，已经很接近。
为什么不是完全一样？因为移动过程中曲线的斜率也在变。
**导数是当前位置的近似，不是可以任意跨很远的固定汇率。**

如果反过来从 0.100 改善到 0.099，$\Delta x=-0.001$，
负斜率乘负变化量得到正数：奖励约增加 0.001810。符号和直觉一致。

当 $x<0$ 时，$R'(x)>0$：从负偏差往 0 走，奖励上升。
因此“奖励随误差变大而下降”指的是 **$|x|$ 变大**，不能把带符号的 $x$ 和误差大小混用。

## 1.11 为什么最敏感的位置是 σ / √2

我们关心的是变化率的**大小**，所以取绝对值。先看右半边 $x\ge0$：

$$S(x)=|R'(x)|=\frac{2x}{\sigma^2}e^{-x^2/\sigma^2}.$$

这里 $S$ 是一个新函数，输出“奖励曲线在这个位置有多陡”。
找最陡的位置，就是找 $S$ 的最高点。

先用数字看，不要求你先会求极值。仍取 $\sigma^2=0.1$：

| 偏差 x | 奖励 R(x) | 敏感程度 S(x) |
|---:|---:|---:|
| 0 | 1.000000 | 0 |
| 0.10 | 0.904837 | 1.809675 |
| 0.20 | 0.670320 | 2.681280 |
| 0.223607 | 0.606531 | 2.712488 |
| 0.30 | 0.406570 | 2.439418 |
| 0.60 | 0.027324 | 0.327885 |
| 1.00 | 0.000045 | 0.000908 |

中间那一行最陡，但它的奖励只有约 0.607，远不是满分。

要证明这个位置，补一条规则：两个函数相乘的导数是
$(fg)'=f'g+fg'$。原因是乘积变化时，两边各自的变化都要算。
把 $S$ 看成常数 $2/\sigma^2$ 乘上 $x$ 和 $e^{-x^2/\sigma^2}$，得到：

$$S'(x)=\frac{2}{\sigma^2}
\left[1\cdot e^{-x^2/\sigma^2}
+x\cdot\left(-\frac{2x}{\sigma^2}e^{-x^2/\sigma^2}\right)\right].$$

两项都有指数项，把它提出去：

$$S'(x)=\frac{2}{\sigma^2}e^{-x^2/\sigma^2}
\left(1-\frac{2x^2}{\sigma^2}\right).$$

前两个因子始终为正，正负只由括号决定：

- $x<\sigma/\sqrt2$：括号为正，$S$ 还在增加。
- $x=\sigma/\sqrt2$：括号为零，$S$ 在这里转弯。
- $x>\sigma/\sqrt2$：括号为负，$S$ 开始减少。

所以这里确实是最大值，不只是“碰巧导数为零”：

$$x_{\text{最敏感}}=\frac{\sigma}{\sqrt2}.$$

本项目 $\sigma=\sqrt{0.1}\approx0.316228$，因此：

$$x_{\text{最敏感}}=\sqrt{0.1/2}=\sqrt{0.05}\approx0.223607\ \mathrm{m/s}.$$

![奖励曲线与敏感程度并排对照](../figures/ch01_reward_sensitivity.png)

图中左侧是奖励，右侧是其对误差导数的绝对值，圆点标出各自最敏感的位置。σ 越小，峰更靠近 0，也更高；但当前误差若远离峰值区域，就未必受益。

这是本章标量速度误差例子的单位。站直项使用的是重力方向分量，不能把它的宽度也读成 m/s。

## 1.12 σ 该怎么选：让当前值得改善的误差能分出高低

“std ≈ the error you still care about”不是要求误差等于 std，
也不是说 std 是误差的最大允许值。它给的是量级上的判断：
**当前仍值得优化的误差，应该落在有明显奖励差异的区间。**

假设现在常见误差是 0.20 m/s，而且改善到 0.19 值得鼓励：

| σ | R(0.20) | R(0.19) | 这意味着什么 |
|---:|---:|---:|---|
| 0.01 | $e^{-400}$ | $e^{-361}$ | 两个都极小，float32 中可能都下溢成 0 |
| $\sqrt{0.1}$ | 0.670320 | 0.696979 | 多拿约 0.026659 分，有可见差异 |
| 10 | 0.999600 | 0.999639 | 两个都几乎满分，差异很小 |

太严格，好比教投篮时“必须距中心 1 mm 才有分”：新手从偏 2 m 进步到偏 20 cm，评分仍几乎不变。
太宽松，好比“偏 5 m 都接近满分”：改进也得不到清楚的区分。
类比只解释评分的分辨能力，不能保证某种宽度必然训练成功。

$\sigma$ 改变时，最敏感位置也移动：

| σ | 最敏感的误差大小 σ/√2 |
|---:|---:|
| 0.1 | 0.070711 |
| 0.316228 | 0.223607 |
| 1.0 | 0.707107 |

若希望最陡位置大约在误差 $d$，可从 $\sigma\approx\sqrt2d$ 开始分析。
这只是这条核的几何关系，**不是自动调参公式**。还要看机器人实际遇到的误差分布、噪声、
其他奖励的大小，以及这个误差是否能被策略改善。走路必然带来的头部周期摆动就是后一种约束，见第 16 章。

乘奖励权重 $w$ 会把整条曲线和斜率放大 $w$ 倍，但不会移动最陡的位置。
因此“调权重”和“调 σ”解决的是不同问题；把一个已下溢为 0 的奖励乘十，也仍然是 0。

## 1.13 这条导数如何影响 PPO，又不是什么

到这里最容易产生一个错误印象：机器人是不是沿着 $R'(err)$ 直接调整关节？
**本项目的 PPO 不这样更新。**

我们刚算的是：固定评分规则时，奖励对误差的敏感程度。
PPO 需要的是：策略网络参数改变时，动作分布怎样改变，以及这些动作的采样结果有多好。
两者的求导对象不同：

| 量 | 改变谁 | 回答什么 |
|---|---|---|
| $dR/d\mathrm{err}$ | 误差 | 评分对一点改善有多敏感？ |
| $\nabla_\theta L$ | 网络参数 θ | 这批数据构成的训练损失，往哪个参数方向下降？ |

当前只需先认识 θ 是“网络里全部可调参数”的统称，$\nabla$ 是“一串导数”；第 3 章会展开。
PPO 的完整路线在第 11–13 章，此处先记住流程：

```text
按当前策略抽动作 → 仿真执行 → 收集奖励与后续状态
                                    ↓
                        估计回报和优势：比预期好多少
                                    ↓
                  重新计算已采样动作在策略下的 log 密度
                                    ↓
                      对策略损失反向传播，更新网络参数
```

奖励在这里是采样得到的数据，通常不沿着“奖励 → 物理仿真 → 动作”反向传播。
即使奖励有不连续的判断，只要能提供统计上的行为差异，策略梯度仍然可以学习。
反过来，奖励曲线很陡也不保证学得快：可能很少采到这一区域，或者噪声和其他奖励盖过了差异。

因此，本章分析斜率的用途是**检查评分能否区分当前行为的改善**，而不是直接算出舵机该转多少。

### 停下来检查是否真的懂了

1. $R'(0.1)=-1.81$，机器人这一步得了负分吗？
2. $\sigma$ 从 0.1 改成 1，最敏感位置往哪里移动？
3. 所有样本的奖励都约为 1，一定说明机器人已经完成目标了吗？
4. PPO 会直接把 $dR/d\mathrm{err}$ 送给电机吗？

**逐题解释**：① 没有，奖励约为 0.905，−1.81 是变化率。
② 从约 0.071 移到 0.707，往更大的误差区域移动。
③ 不一定，可能是 σ 太宽，差的行为也拿到高分。
④ 不会，PPO 用采样奖励构造优势，再更新动作分布的参数。

## 📍 映射到项目

> 这一节只需要"看一眼"。看不懂代码语法完全没关系——`torch`、`dim=1` 这些第 6 章之后才讲。
> 目标只是让你知道：**刚学的公式，在仓库里长这样**。

**这段代码做什么**：拿机器人实际的前进/侧移速度，减去指令要它走的速度，得到偏差；
把偏差平方；再加上"上下蹿"的速度平方（机器人不该上下蹿，所以目标是 0）；
最后套 1.8 节的钟形打分。

文件 `.venv/lib/python3.12/site-packages/mjlab/tasks/velocity/mdp/rewards.py`，函数 `track_linear_velocity`：

```python
xy_error = torch.sum(torch.square(command[:, :2] - actual[:, :2]), dim=1)
#          ↑ (指令速度 − 实际速度)，前后和左右两个方向各算一个，平方后加起来 = 偏差²
z_error = torch.square(actual[:, 2])
#          ↑ 上下方向的实际速度，平方（目标是 0，所以不用减）
lin_vel_error = xy_error + z_error
#          ↑ 两部分加起来，就是公式里的 偏差²
return torch.exp(-lin_vel_error / std**2)
#          ↑ exp(−偏差² / σ²)，一模一样
```

**它的宽容度**在 `src/mjlab_microduck/tasks/microduck_velocity_env_cfg.py` 里设的：
`std = math.sqrt(0.1)`，所以 `std**2 = 0.1`。写成"根号 0.1"是为了让读的人一眼看到 σ² 是 0.1。
角速度那一项是 `sqrt(0.5)`，站直那一项是 `sqrt(0.05)`——就是图里的三条线。

## 本章小结

用人话：

- **函数**：确定的机器，喂一个数吐一个数。奖励规则、策略、损失都是函数。
- **斜率 / 变化率**："变了多远 ÷ 走了多久"。直线处处一样。
- **导数** $f'(x)$：曲线上某一点的瞬时变化率，"缩小步长看它逼近哪个数"。正负号告诉你往哪调。
- **链式法则**：机器串机器，倍数相乘。反向传播就是它。
- **$e^{-x}$**：从 1 衰减到 0、永不为负——天然的"分数"。
- **钟形打分** $\exp(-\text{偏差}^2/\sigma^2)$：项目的核心奖励形状，σ 是宽容度。
